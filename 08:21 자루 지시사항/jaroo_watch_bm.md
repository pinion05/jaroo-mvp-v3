# Jaroo 포트폴리오 워치 — 구독 BM 설계

작성: 2026-05-28
한 줄: **물린 종목을 계속 지켜보다가, 상황이 바뀌면 먼저 알려주는 월 구독.**

---

## 1. 왜 이 BM인가

### 문제 — 기존 진단앱의 한계
- 딥스캔은 **일회성 스냅샷**. 한 번 진단하면 관계 끝, 재과금 안 됨.
- 근데 실제 사용자(물린 사람)는 **몇 달~몇 년을 버틴다.**
- 이 긴 기다림 동안 계속 불안하지만, 앱은 아무것도 안 해줌.

### 통찰 — 처분효과(disposition effect)
- 사람은 오른 건 빨리 팔고, 내린 건 안 판다.
- 이유: **매도 = 손실 확정 = 실패 인정.** 안 팔면 "아직 잃은 거 아냐"로 미룰 수 있음.
- 결론: **손절을 강요해도 사람들은 안 한다.** 이건 바꿀 수 없는 현실.

### 전략 — 기다림에 올라타기
- 손절 유도가 목적이 아님. 어차피 버틸 거, **제대로 버티게** 해주고 과금.
- 버티는 시간 = 구독 기간. 일회성 진단 → 지속 구독으로 전환.

---

## 1-B. 사용자 두 유형 — 이게 BM의 뼈대

물린 사람은 손실을 대하는 방식이 정반대로 갈린다:

```
유형 1: 계속 쳐다봄  → 불안해서 매일 확인, 뉴스 뒤짐, 정보 과잉
유형 2: 아예 안 봄    → 물린 순간 앱 삭제, 계좌 안 엶, "없는 셈" 회피
```

**유형 2가 처분효과의 더 극단적 형태.** 손실을 마주하는 게 고통스러우니 아예 안 보는 걸로 회피 — "계좌를 안 열면 손실도 없는 것 같다"(타조 효과).

### 워치는 유형별로 다르게 작동한다
| | 유형 1 (계속 봄) | 유형 2 (안 봄) |
|---|---|---|
| 문제 | 정보 과잉, 불안 증폭 | 결정적 순간도 놓침 |
| 워치 역할 | **필터** — 중요한 것만 걸러줌 | **대리 감시** — 대신 봐줌 |
| 파는 것 | 피로 감소 ("매일 안 봐도 됨") | **안심 ("안 봐도 안전")** |

### 유형 2가 어렵지만 진짜 기회인 이유
- **어려움**: 앱을 안 켠다 → 리텐션 0에 수렴. 손실 알림은 더 회피.
- **기회**: 안 보는 사람일수록 "대신 봐주는" 가치가 크다. 그리고 **구독은 앱을 안 켜도 유지된다.**
- → **보험 구조.** 평소 신경 안 써도, 있으면 안심되고, 매달 돈 낸다. 유형 2한테 파는 건 **"안심"** — 손실을 안 봐도 되게 해주면서(회피 충족), 진짜 위험할 때만 조용히 깨운다(최악 방지).

```
유형 1 구독:  "매일 볼 필요 없게 걸러줌"    (피로 감소)
유형 2 구독:  "안 봐도 대신 지켜봄"          (회피 보장 + 안심)
공통 축:      "당신 대신 지켜본다"
```

## 2. 핵심 가치 — "변화가 생기면 먼저 알려준다"

물린 사람의 진짜 공포 = **"나빠지고 있는데 나만 모름."**
이걸 지켜봐주는 게 구독의 본질. 버티는 시간 순서로 세 가지 얼굴:

```
버티는 중   → [파수꾼]  "지금은 버틸 근거 있어요" + 나빠지면 감지
                ↓
신호 발생   → [코치]    "펀더멘털이 깨졌어요, 손절 고민할 시점"
                ↓
회복 국면   → [동행자]  "본전까지 +8% 남았어요" 탈출 기회 추적
```

셋은 별개 컨셉이 아니라 **한 구독 안의 상황별 대응**. 관통하는 축은 "변화 감지 + 선제 알림".

### 딥스캔(일회성)과의 결정적 차이
| | 딥스캔 (일회성) | 워치 (구독) |
|---|---|---|
| 성격 | 그 순간의 스냅샷 | 시간에 걸친 감시 |
| 가치 | "지금 어떤가" | **"바뀌면 먼저 알려줌"** |
| 사용자 공포 대응 | — | "나만 모름"을 해소 |

→ "딥스캔 한 번 더 사면 되잖아"라는 반론의 답: **딥스캔은 변화를 못 잡는다. 워치는 변화를 잡는다.**

## 3. 무엇을 감지해서 알리나 (트리거) — 초안

버티는 사람에게 매일 알림은 피곤함. **의미 있는 변화**에만 알림.

### 3-1. 손절 고려 신호 (코치)
- 펀더멘털 훼손: 영업이익 적자 전환, 부채 급증, 지배구조 리스크
- 기술적 붕괴: 주요 지지선 이탈, 거래량 동반 하락
- 알림 예: "OO의 실적이 적자 전환했어요. 버틸 근거가 약해지고 있어요. 다시 볼까요?"

### 3-2. 본전 근접 / 탈출 기회 (동행자)
- 본전까지 거리 추적, 근접 시 알림
- 알림 예: "본전까지 +3%예요. 탈출 여부를 고민할 지점이에요."

### 3-3. 반등 / 추가매수 기회 (동행자)
- 저점 반등 신호, 평단 낮출 기회 (신중히 — 물타기 조장 주의)
- 알림 예: "반등 신호가 보여요. 다만 추가매수는 신중하게 판단하세요."

### 3-4. 주기적 안심 (파수꾼)
- 변화 없을 땐 조용히. 대신 주 1회/월 1회 "요약"
- "이번 주 OO은 버틸 근거 유지 중이에요. 특이사항 없어요."
- → 아무 일 없어도 구독 가치를 느끼게 (안심도 상품)

**설계 원칙**: 알림 과다 = 이탈. "변화 있을 때만 + 주기 요약" 조합. 사용자가 알림 종류를 켜고 끌 수 있게.

### 3-5. 유형 2(회피형)를 위한 알림 원칙 — 극도로 섬세하게
유형 2는 "손실 알림"을 극도로 싫어함. 잘못하면 알림 끄고 이탈.
- **평소엔 침묵.** 아무 일 없으면 조용히. (유형 1의 "주기 요약"도 유형 2에겐 끌 수 있게)
- **결정적일 때만** 신호. 빈도 최소.
- **"손실" 프레임 금지 → "행동 필요" 프레임.**
  - 나쁨: "OO −23% 손실 중" (보기 싫은 걸 들이밈)
  - 좋음: "OO에 지금 확인이 필요한 변화가 생겼어요." (중립, 손실 언급 X)
- 핵심 조합: **"평소 안심시키는 침묵 + 결정적 순간의 조용한 신호."** 시끄러우면 도망감.

### 3-6. 알림 강도 — 사용자가 직접 고름
유형 1/2를 우리가 추측하지 않고 **사용자가 자기 상태를 고르게** 한다. (사람은 시기에 따라 달라짐 — 고정 유형이 아니라 상태)

| 선택지 | 내용 | 빈도 |
|---|---|---|
| **안 보고 싶어요** | 버틸 근거 깨짐 / 본전 근접만. 주간 요약도 없음 | 월 1~2회 |
| **적당히 알려줘요** (기본) | + 실적·공시, 근거 변화, 주 1회 요약 | 주 1~2회 |
| **다 알고 싶어요** | + 업황·공급망·미국장 영향, 5% 이상 급등락 | 주 3~5회 |

- 이벤트 3층(§7)과 매핑: 최소=층1 핵심 / 보통=층1 전부 / 상세=층1+층2. **층3은 어느 단계에서도 안 감.**
- **안전 하한선**: 거래정지·상장폐지 위험, 버틸 근거 완전 붕괴는 "안 보고 싶어요"에서도 반드시 발송. 끌 수 없음을 화면에 명시 → 안심하고 최소를 고를 수 있게.
- **상황별 자동 제안**: "다음 주 실적 발표예요. 그 주만 늘릴까요? 끝나면 원래대로 돌아가요."
- **종목별 개별 설정은 두지 않음.** 대신 손익 상태 보고 자동 차등(손실 종목 더 챙김, 수익 종목 조용히). 이유: 설정 세분화는 대다수가 안 쓰고, 특히 "안 보고 싶어요"를 고른 사람에게 종목별 설정을 시키는 건 모순.
- **이탈 방지 효과**: 알림이 많아 짜증나면 보통 앱 삭제/알림 전체 차단으로 감. "안 보고 싶어요"라는 중간 선택지가 있으면 **완전 이탈 대신 강도만 낮추고 구독은 유지**.

### 3-7. 실시간 보고서는 만들지 않는다
"매일 종목 보고서 생성"은 세 가지로 실패:
1. **워치의 약속과 충돌** — "안 보셔도 괜찮아요"인데 매일 볼 게 생김
2. **비용 초과** — 딥스캔 1회 = LLM 60초. 3종목 매일이면 월 90회, 구독료를 넘김
3. **쓸 말이 없음** — 대부분의 날은 의미 있는 변화가 없어 공허한 문장을 지어내게 됨 → 신뢰 훼손

**대신 3단 구조:**
| 주기 | 무엇 | LLM |
|---|---|---|
| 매일 | 지표 감시 (본전거리·급락·공시·D-day) | ✗ 계산만 |
| 주 1회 | 주간 요약 ("특이사항 없어요") | ✗ 템플릿 |
| 이벤트 시 | 딥스캔 재분석 + 판단 갱신 | ✓ 실행 |

**감시는 매일, 분석은 이벤트 때만.**

## 4. 과금 모델 — 초안 (선택 필요)

세 가지 안. 각각 장단:

### 안 A — 포트폴리오 전체 월 구독
```
월 정액 → 보유 종목 전부 감시
예: 월 9,900원 (종목 수 무관)
```
- 장점: 단순, 종목 많은 사람에게 유리, 손절해도 다른 종목 계속 관리 → 관계 지속
- 단점: 종목 1개만 물린 사람에겐 비싸 보임

### 안 B — 종목당 월 구독
```
물린 종목 1개당 월정액
예: 종목당 월 2,900원
```
- 장점: 물린 종목만 골라 등록, 진입장벽 낮음
- 단점: 손절하면 그 종목 구독 끝 → **BM이 손절 억제 유인** (위험!)

### 안 C — Pro 등급에 포함
```
Jaroo Pro 월 구독 → 딥스캔 무제한 + 워치 포함
예: 월 4,900원
```
- 장점: 기존 Pro와 통합, 단순한 가격표, 딥스캔+워치 묶음 가치
- 단점: 워치만 원하는 사람에게 과할 수 있음

**추천: 안 A 또는 C.** 안 B는 "종목 손절 = 구독 해지"라 손절 억제 유인이 생겨 위험(§6 참조). 포트폴리오 단위나 Pro 통합이 유인 정렬에 안전.

### 4-B. A vs C 정면 비교 (최종 후보)
| 기준 | A. 포트폴리오 전체 월정액 | C. Pro에 포함 |
|---|---|---|
| 가격 예시 | 월 9,900원 (워치 단독) | 월 4,900원 (딥스캔 무제한+워치) |
| 소비자 인식 | "지켜봐주는 서비스"가 명확 | "다 되는 프리미엄" |
| 유형 2(회피형) 적합 | 높음 — "안심 보험" 딱 맞음 | 중간 — 딥스캔 무제한이 안 보는 사람에겐 잉여 |
| 딥스캔 건별 매출 | 유지됨 (워치와 별개) | 잠식 (무제한이라 건별 소멸) |
| 가격표 복잡도 | 상품 2개(딥스캔 건별 + 워치 구독) | 상품 1개(Pro) — 단순 |
| 확장성 | 워치 티어링 가능(종목 수·감시 강도) | Pro 한 덩어리라 세분화 어려움 |

**판단 포인트**:
- 유형 2("안심 보험")를 주력으로 보면 → **A** (워치를 독립 상품으로, 보험처럼 포지셔닝)
- 단순한 가격표 + 딥스캔 자주 쓰는 헤비유저 묶기 → **C**
- 절충: **A를 기본, Pro는 A+딥스캔무제한 상위 번들**로 두면 둘 다 살림. (워치=보험 독립상품 유지하면서, 헤비유저는 Pro로)

### 4-C. 무료 체험 — 확정
**며칠간 전체 무료 체험** (첫 등록 시 N일 전체 기능 개방 → 이후 유료 전환).
- 유형 2에 특히 유효: 부담 없이 "지켜봐줌"을 경험 → "안 봐도 안전하네" 체감 후 전환.
- 체험 종료 임박 시 알림: "체험이 곧 끝나요. 계속 지켜봐드릴까요?" (회피 욕구 자극 안 하는 중립 톤)
- 체험 기간(N일)은 검증 필요 — 변화가 한 번은 감지될 만큼 길어야 가치 체감(7일? 14일?).

## 5. 화면 흐름 (구현 시)

```
[홈] 물린 종목 카드
  └ "이 종목 지켜보기" → 워치 등록 유도

[워치 대시보드] (신규)
  ├ 감시 중인 종목 리스트
  ├ 각 종목: 상태 라벨 + 본전까지 거리 + 마지막 신호
  └ "최근 알림" 타임라인

[알림] 변화 발생 시 푸시
  └ 탭하면 → 해당 종목 재진단(딥스캔)으로

[마이페이지]
  └ 워치 구독 관리 (현재 "준비 중" 자리)
```

- 마이페이지의 Pro 자리가 **포트폴리오 워치 카드**로 교체됨 (지켜보는 종목 수, 다음 확인 시점, 알림 설정 요약, 관리 버튼).
- 홈 종목카드 펼침에 **[딥스캔 분석] [지켜보기]** 나란히 — 손실 종목은 지켜보기 강조.
- 워치 알림 → 딥스캔 재진단으로 이어지는 순환 (구독 + 건별 결합 가능).

### 5-B. 유형 2 도달 전략 — "떠나기 직전에 잡기"
유형 2는 곧 앱을 안 켠다. 그래서 **아직 앱을 볼 때(물린 직후)** 워치로 전환시켜야 함.
```
물린 종목 확인 (아직 볼 때)
  └ "이 종목, 안 보셔도 저희가 지켜볼게요" → 워치 등록
       └ 이후 사용자는 앱 안 켜도 → 구독 유지 + 결정적일 때만 알림
```
- 등록 시점 카피: 회피 욕구를 인정 — "매번 확인하는 거 힘드시죠. 대신 지켜봐드릴게요."
- 한 번 등록되면 앱 리텐션과 무관하게 구독 유지 (보험처럼).
- 무료 체험(첫 종목 무료 감시)이 특히 유형 2 전환에 유효 — 부담 없이 "지켜봐줌"을 경험.

## 5-C. 이벤트 처리 3층 — "내 종목과 연관되는가"

알림 여부의 단일 기준: **내 종목과 연관되는가.**

```
층 1 (알림 O)   내 종목 직접 — 실적·공시·수주·증자·대주주 변동
층 2 (기록만)   배경 — 미국장·환율·업황·공급망
                → "SFA반도체 영향: 제한적/긍정적" 으로 번역해 기록
층 3 (차단)     무관 — 테마주·루머·타 업종  → "147건 걸러냈어요"
```

**연관 판정 경로**: 직접(내 종목 공시) / 업종(반도체 업황→SFA) / 공급망(삼성 투자→협력사) / 거시(미국 반도체주→내 종목, 영향도 판단)

**번역 원칙 — 알림은 항상 종목명으로 시작:**
- 나쁨: "미국 나스닥 3% 급락" (남 얘기, 공포만 유발)
- 좋음: "SFA반도체에 영향이 있을 수 있어요. 어젯밤 미국 반도체주가 빠졌어요. **영향은 제한적이고, 버틸 근거는 그대로예요.**"
- 영향 여부만 알리면 불안만 커짐 → **"내 근거는 어떻게 됐나"까지** 말해야 안심이 됨.

**예고**: 예정 이벤트는 미리 (D-3 "다음 주 실적이에요"). 예측 가능성이 안심을 줌 — 특히 유형 2가 "그때만 보면 되는구나" 하고 안심.

**갱신**: 이벤트가 발생하면 "버틸 근거 조건 체크리스트"를 다시 채점 → 살아있는 문서가 됨.

## 6. 유인 정렬 — 반드시 지킬 원칙

**위험: "기다림을 팔면" jaroo가 사용자를 계속 버티게 만들 유인이 생긴다.**
- 사용자가 손절 → 구독 끝 → 매출 끊김
- → jaroo가 은근히 "더 지켜보세요" 하고 **버티기 조장** 가능
- → 처분효과를 **악용**하는 나쁜 앱이 됨 (사용자 이익과 충돌)

**원칙: "기다림을 파는 게 아니라, 좋은 결정을 판다."**
- 손절 신호는 **정직하게** 준다. 팔아야 할 때 팔라고 한다.
- 사용자가 손절하면 → "잘 파셨어요, 다음 종목 찾아드릴게요"로 **관계 지속**
- 한 종목 손절 = 구독 종료 X. 포트폴리오/다음 종목으로 이어짐 (→ 그래서 과금은 §4 A/C안)

```
나쁜 BM:  버틸수록 돈 벎 → 손절 막음 → 사용자 손해
좋은 BM:  좋은 결정마다 돈 벎 → 손절도 매수도 가치 → 사용자 이익과 일치
```

## 7. 감정 프레이밍 (화면 카피 원칙)

물린 사람의 "손실 확정 공포"를 다루는 카피 톤:

- **안 파는 마음 부정 안 함**: "안 팔고 싶은 마음, 이해해요."
- **현실은 정확히**: "다만 지금 상황은 이래요" (숨기지 않음)
- **손절 = 선택으로 리프레이밍**: "손절은 실패가 아니라 다음 기회를 위한 자금 회수예요."
- **기다림에 근거 부여**: 막연한 "언젠가 오르겠지" → "기다릴 근거가 있는지" 판단해줌
