2데이터 계약 — 서버가 주고받기로 한 약속

"계약"이라는 건 서버가 어떤 모양(JSON)으로 데이터를 주겠다는 약속이에요. 약속만 정해지면 화면 만드는 사람과 서버 만드는 사람이 따로 작업할 수 있어요. 5가지 계약이 있어요:

계약경로중학생 설명
2-1 OCR 결과POST /api/ocr/parse증권사 앱 스크린샷을 보내면 읽은 종목 목록을 돌려줌. 이름이 확실하면 matched:true, 애매하면 matched:false+후보 2개 제시(빈 칸 치라고 하지 않음!)
2-2 홈GET /api/portfolio총 평가금액·손익·상태 라벨(강세/우세/관찰/주의/위험)·종목 카드 뭉치
2-3 딥스캔GET /api/deepscan/{code}즉시 나오는 시세(instant)와 40~60초 뒤 나오는 AI 분석(llm)을 따로 줌
2-4 워치GET /api/watch감시 중 종목의 본전까지 거리, 버틸 근거 조건 3개, 다가오는 이벤트(D-day), 걸러낸 뉴스 수
2-5 추가매수 계산(서버 호출 없음)아래 공식만 있으면 화면에서 바로 계산 — 아래 실습에서 직접 해보세요!

"더 살까?" 고민할 때 쓰는 계산기예요. 숫자를 바꿔보면 공식이 어떻게 움직이는지 느껴질 거예요. (주·평단·현재가는 문서 1 §2-2 삼성전자 계약 예시, 52주 저가 12,100원은 §2-3 딥스캔 계약 예시에서 인용)

새 수량 newQty
–

–
본전까지 gapPct
–

–

–

newQty  = qty + add
newAvg  = (avg * qty + current * add) / newQty

cost    = current * add
gain10  = current * 0.10 * newQty        // 10% 등락 시 손익
worst   = |(week52Low - newAvg) * newQty|
gauge%  = gapPct / baseGapPct * 100      // 게이지 채움 비율

4디자인 토큰 — 앱의 색·글자 규칙

토큰은 "이 색은 무조건 이 용도"라고 정해둔 약속이에요. 한국 증시에서는 빨강=오름, 파랑=내림이에요 (다른 나라와 반대!). 색칠판을 눌러보세요.

실습 — 색 팔레트 (클릭해 보세요)
색을 누르면 설명이 나와요.
  • 액션(버튼·링크·토글)은 무조건 먹색. 손익 색을 버튼에 쓰지 않아요.
  • 빨강/파랑은 손익 전용 — 앱에서 유일한 컬러예요. 그래야 "색=내 돈 상태"가 명확해져요.
  • 구글 로고만 공식 4색 예외 (브랜드 규정이라 어쩔 수 없음).
  • 도넛(비중 그래프) 조각은 중립 청회색 3종 — 빨강/파랑과 헷갈리지 않게.

5-1. 정보 밀도 — 결론 먼저, 나머지는 접기

6비즈니스 로직 — 앱의 두뇌 6가지

6-1. OCR 매칭 정규화 ★필수

증권사 앱(MTS)마다 종목 이름 표기가 달라요. DB엔 #삼성스팩, 스크린샷엔 삼성스팩이라고 찍혀 있으면 그냥 비교하면 "다른 종목"이 돼버려요. 그래서 비교용 "키"를 따로 만들고, 저장은 원본 이름으로 해요.

실습 — 정규화 기계 (직접 쳐 보세요)
DB 후보와 비교 (원문 예시)
정규화: 공백 제거 → # 제거 → 양끝 특수기호 제거 → 대소문자 통일

DB "#삼성스팩"  → 키 "삼성스팩"
OCR "삼성스팩"  → 키 "삼성스팩"   → 매칭 성공

후보 유사도도 정규화 키 기준으로 계산. 화면 표시·저장은 DB 정식 명칭 사용.

6-2. 계좌 병합

같은 종목을 여러 계좌에서 샀다면: 홈에서는 하나로 합쳐서(평단 = 가중평균) 보여주고, 계좌별 내역은 따로 보관해요. 딥스캔은 계좌마다 평단이 다르므로 내역이 필요해서예요.

6-3. 이벤트 3층 분류 — 뉴스를 어디로 보낼까

층대상처리
1층내 종목 직접 (실적·공시·수주·증자·대주주)알림 발송
2층배경 (미국장·환율·업황·공급망)기록만 — "내 종목 영향: 제한적/긍정적"으로 번역
3층무관 (테마주·루머·타 업종)차단 — filtered_count에만 반영

연관 판정 경로: 직접 / 업종 / 공급망 / 거시(영향도 판단). 그리고 알림 문구는 항상 종목명으로 시작해요. "나스닥 3% 급락" ✗ → "SFA반도체에 영향이 있을 수 있어요" ✓

실습 — 3층 분류 퀴즈 (내가 심사관!)

6-4. 알림 강도 — 3단계 + 안전 장치

실습 — 알림 강도 고르기
안전 하한선 (설정 무관 항상 발송): 거래정지·상장폐지 위험, 버틸 근거 완전 붕괴 — 이 둘은 "안 보고 싶어요"를 골라도 끌 수 없어요.
자동 차등: 손실 종목은 강도를 한 단계 높게, 수익 종목은 낮게 (사용자 설정 없이).

6-5. 감시 주기 — 실시간 보고서 생성 금지

주기작업AI(LLM) 사용?

## 6. 비즈니스 로직

### 6-1. OCR 매칭 정규화 ★필수
MTS마다 종목명 표기가 달라 매칭 실패가 발생. **비교용 키를 정규화**하되 저장은 원본 명칭:
```
정규화: 공백 제거 → # 제거 → 양끝 특수기호 제거 → 대소문자 통일

DB "#삼성스팩"  → 키 "삼성스팩"
OCR "삼성스팩"  → 키 "삼성스팩"   → 매칭 성공
```
- 후보 유사도도 정규화 키 기준으로 계산
- 표시·저장은 **DB 정식 명칭** 사용

### 6-2. 계좌 병합
```
포트폴리오 뷰: 종목 합산 (평단 = 가중평균)  → 비중·전체손익 계산용
계좌별 내역:   분리 보관                     → 딥스캔은 계좌별 평단이 다르므로
```

### 6-3. 이벤트 3층 분류
| 층 | 대상 | 처리 |
|---|---|---|
| 1 | 내 종목 직접 (실적·공시·수주·증자·대주주) | **알림 발송** |
| 2 | 배경 (미국장·환율·업황·공급망) | **기록만** — "내 종목 영향: 제한적/긍정적"으로 번역 |
| 3 | 무관 (테마주·루머·타 업종) | **차단** — `filtered_count`에만 반영 |

연관 판정: 직접 / 업종 / 공급망 / 거시(영향도 판단)
**알림 문구는 항상 종목명으로 시작.** "나스닥 3% 급락" ✗ → "SFA반도체에 영향이 있을 수 있어요" ✓

### 6-4. 알림 강도
| 값 | 라벨 | 발송 대상 | 빈도 |
|---|---|---|---|
| `minimal` | 안 보고 싶어요 | 층1 핵심(근거 붕괴·본전 근접)만. 주간 요약 없음 | 월 1~2 |
| `normal` | 적당히 알려줘요 | 층1 전부 + 주 1회 요약 | 주 1~2 |
| `detailed` | 다 알고 싶어요 | 층1 + 층2 + 5% 이상 급등락 | 주 3~5 |

**안전 하한선 (설정 무관 항상 발송)**
- 거래정지·상장폐지 위험
- 버틸 근거 완전 붕괴

**자동 차등**: 손실 종목은 강도를 한 단계 높게, 수익 종목은 낮게 (사용자 설정 없음)

### 6-5. 감시 주기 — 실시간 보고서 생성 금지
| 주기 | 작업 | LLM |
|---|---|---|
| 매일 | 지표 감시 (본전거리·급락·공시·D-day) | ✗ 계산만 |
| 주 1회 | 주간 요약 (템플릿) | ✗ |
| 이벤트 발생 시 | 딥스캔 재분석 + 조건 재채점 | ✓ |

이유: 매일 LLM 호출 시 구독료 초과 + 대부분의 날은 쓸 내용 없음

### 6-6. 딥스캔 실패 처리
- **크레딧 차감 금지** (화면에 "차감되지 않았어요" 명시)
- `instant` 데이터는 조회됐으므로 "시세 정보만 보기" 제공

# Jaroo 분석 결과 화면 — 개발 전달 명세 (v7 기준)

기준 프로토타입: `jaroo_final_v7.html`
한 줄 요약: 종목 탭 → 시세 즉시 브리핑(움직임) → 세 팀 분석 → 종합 결론. 한 페이지, 끊김 없이 이어짐.

---

## 0. 핵심 설계 원칙

1. **시세(즉시 가능) vs LLM(느림) 분리** — 시세 조회로 나오는 건 0초부터 보여주고, LLM 분석만 기다린다.
2. **기다림을 브리핑으로 채운다** — LLM 도는 동안 빈 화면 대신, 시세 데이터를 가공한 브리핑을 움직임과 함께 단계적으로 보여준다.
3. **점수 없음** — 강세 라벨 + 5단계 막대 + 팀 의견 분포로 대체 (정밀 점수 모순 제거).
4. **결론에 "답"** — 상태(강세)뿐 아니라 행동(보유 유지 시나리오)까지.

## 1. 데이터 도착 시점 (중요)

| 데이터 | 도착 | 비고 |
|---|---|---|
| 현재가, 손익률, 손익액 | 즉시 | 실시간 시세 조회 (분석 시작 시 1회) |
| 시/고/저, 거래량, 52주 고저 | 즉시 | 동일 조회 |
| 전일 종가/거래량 | 즉시 | 동일 조회 |
| 코스피/코스닥 지수 | 즉시 | 동일 조회 |
| 일봉 (3개월) | 즉시 | 차트용 |
| 평단/보유수량 | 즉시 | OCR 데이터 (사용자) |
| **목표가, 상승여력, 투자의견** | **지연** | 크롤링/LLM (≈40~60초, 캐시 시 10~20초) |
| **세 팀 분석 요약** | **지연** | LLM (병렬, 캐시 시 빠름) |

- 안 되는 것: 실시간 수급(외국인/기관), 호가 → 화면에서 제외

## 3. 타이밍 (LLM 시간에 비례하여 동적)

데모 기준(LLM 60초 가정):

| 시점 | 동작 |
|---|---|
| 0~5초 | 일봉 차트가 왼→오 그려짐 |
| 6,11,16,22,28,33초 | 브리핑 6개 순차 등장 (각 항목 제목→데이터→의미 펼침) |
| ~38초 | 브리핑 끝 → 합친 박스 등장 (전환멘트+카운트다운) |
| 38~48초 | LLM 대기 (타이핑 인디케이터) |
| 48,50.5,53초 | 세 팀 순차 등장 (타이핑→텍스트) |
| ~56초 | 종합 결론 (막대 순차 점등 + 시나리오 바 채움) |

**캐시된 종목(LLM 10~20초) 대응:** 브리핑 간격을 LLM 예상 시간에 맞춰 압축.
```
브리핑 간격 = (LLM예상시간 − 차트시간) / 브리핑개수
LLM 15초 → 간격 2초, LLM 60초 → 간격 8초
```
같은 화면·항목, 속도만 다르게. LLM 끝나는 시점에 브리핑도 자연스럽게 끝나도록.

## 4. 인트로 (손익 5단계 동적)

종목명 + 손익 상황 한 줄. **금액 없이**, 상황만.

| 구간(전체자산 대비) | 인트로 |
|---|---|
| +20%↑ | "{종목}, 꽤 오르셨네요" |
| +3~20% | "{종목}, 수익 구간이에요" |
| −3~+3% | "{종목}, 거의 본전이네요" |
| −15~−3% | "{종목}, 조금 빠졌네요" |
| −15%↓ | "{종목}, 쉽지 않은 구간이네요" |

판정 기준 = **전체 자산 대비 충격** (`손익액 / 전체 포트폴리오 평가액`), 종목 손익률 아님.
(종목 −10% 여도 전체 비중 작으면 가벼운 톤)

## 5. 시세 카드

### 5-1. 헤더
현재가, 손익률/액(색: 수익 초록 #1A9D55 / 본전 회색 #5A6473 / 손실 빨강 #E5484D), 평단·보유수량.

### 5-2. 일봉 차트
- 최근 3개월 일봉, 왼→오 그려지는 애니메이션 (≈5초, LLM 시간 따라 조정)
- **내 평단 점선(가로)** + 라벨
- 현재가가 평단 위=초록 선, 아래=빨강 선 + 영역 음영
- 끝점(현재가) 깜빡이는 링

### 5-3. 브리핑 6개 (단계 펼침)
각 항목 = **질문 → 데이터 → 의미** 3단계로 펼쳐짐 (제목 0s, 데이터 +1.2s, 의미 +2.4s). 숫자는 카운트업.

순서 (큰 그림 → 현재, 희망 먼저):

| # | 질문 | 데이터 | 의미 | 출처 |
|---|---|---|---|---|
| 1 | 최근 한 달 흐름? | +12.3% | 바닥 다지고 회복 중 | 일봉 |
| 2 | 단기 흐름은? | 3일 연속 상승 | 흐름 살아남 | 일봉 |
| 3 | 내 자리는? | 본전까지 +0.4% | 고점서 샀지만 55원이면 회복 | 현재가+평단 |
| 4 | 오늘 시장 속? | 코스피+0.8/코스닥−0.3/내종목+0.2 | 시장 좋은데 덜 따라옴 | 지수+현재가 |
| 5 | 오늘 하루? | 반등 흐름 | 저가서 올라 고가 부근 | 시/고/저 |
| 6 | 거래는? | 어제의 1.4배 | 관심 붙은 하루 | 거래량+전일 |

카피 원칙: 희망적 먼저, 아픈 사실(고점 대비 손실)은 긍정 프레임("55원이면 회복"). 질문형은 과하지 않게.

## 6. 합친 박스 (전환 + 대기)

브리핑 끝 → 세 팀 등장 전, **하나의 박스**:
```
시세는 다 봤어요. 이제 세 팀이 더 깊이 분석하는 중이에요.
─────
⟳ [진행 상태 텍스트]              0:10
```
- 전환 멘트(위) + 스피너·카운트다운(아래) 한 박스
- 카운트다운 = 세 팀 도착까지 남은 시간
- 세 팀 도착 시 박스 통째로 사라짐(슬라이드 업)

## 7. 세 팀 (LLM 요약 + 근거 펼침)

각 팀: 아바타 + 이름 + 부제(소속 3명) + LLM 요약 + 태그 2개 + **근거 펼침**.

| 팀 | 부제 | 담당 |
|---|---|---|
| 시장·차트 팀 | 차트 마스터·거래량·상승세 추적 | 가격위치·추세·거래량 |
| 심리·환경 팀 | 증권사 의견·산업 전문가·이슈 탐색 | 목표가·산업·이벤트 |
| 가치·기본 팀 | 가치 분석·성장 전략·재무 점검 | 수익성·밸류·지배구조 |

**등장:** 타이핑 인디케이터(● ● ●) → LLM 도착 시 텍스트로 교체, 순차(2~3초 간격).

**근거 펼침 (기본 접힘):** LLM 요약은 그대로, 펼치면 그 팀 요약의 **출처 정형 수치** (LLM 미경유).

| 팀 | 근거 데이터 (시세로 가능한 것만) |
|---|---|
| 시장·차트 | 현재가 / 20일 이동평균 / 52주 위치 / 거래량(전일 대비) |
| 심리·환경 | 평균 목표가 / 투자의견 / 분석 리포트 수 / 최근 변동 |
| 가치·기본 | 영업이익 / PER·PBR / ROE / 지배구조 |

※ 수급(외국인/기관)은 실시간 불가 → 근거에서 제외.

**카피 원칙:**
- 세 팀이 같은 말 반복 금지. "상승 여력"은 결론에만, 팀 요약엔 X.
- 어조 통일: 정중한 친근체 "~이에요/예요".
- 단정·보장 표현 금지 ("추가 리스크 없음" → "추세 이탈 시 검토").
- 팀 간 의견 중복 금지 (밸류 우려는 가치·기본 팀에만).

## 8. 종합 결론 (상태 + 답 + 근거)

순서대로:

### 8-1. 상태

- 5단계 막대 ●●●●○ (순차 점등 애니메이션)
- "3팀 중 2팀 긍정 · 1팀 중립" 의견 분포

**막대/라벨 = 팀 verdict 집계로 계산** (정밀 점수 불필요):
| 긍정 팀 | 막대 | 라벨 |
|---|---|---|
| 3 | ●●●●● | 강세 |
| 2(+중립1) | ●●●●○ | 강세 |
| 2(+부정1)/1+중립2 | ●●●○○ | 우세 |
| 전부 중립 | ●●○○○ | 관찰 |
| 부정 우세 | ●●○○○~●○○○○ | 주의 |
| 3 부정 | ○○○○○ | 위험 |

### 8-2. 종합 문장 (한 줄)
손익 상황 + 판단. 예: "거의 본전이고 상승 여력이 남아 있어, 지금 서둘러 정리하기보다 1–2주 더 지켜보는 게 좋겠어요."
(손익 5단계 톤 반영)

### 8-3. 추천 행동 (시나리오, 합 100%)
| 행동 | 비율 | 트리거 |
|---|---|---|
| 보유 유지 [추천] | 62% | 목표가 도달 시 분할 매도 |
| 추가 매수 | 23% | −10% 도달 시 평단 낮추기 |
| 손절 | 15% | 지금 팔면 −877원 · 추세 이탈 시 검토 |

- 합 정확히 100% (정규화 필수)
- 손절에 즉시 매도 시뮬(지금 팔면 얼마) 통합
- 바 채워지는 애니메이션

### 8-4. 근거 숫자 (그리드)
평균 목표가 / 상승여력 / 투자의견 / 증권사 수. (지연 데이터, 결론과 함께 도착)

```jsonc
    "current", "open", "high", "low", "volume", "prev_close", "prev_volume",
    "week52_high", "week52_low", "avg_price",
    "daily": [ {date, close} ],                       // 일봉 3개월
    "kospi_pct", "kosdaq_pct"
  },
  "llm_eta_sec": 15,                                   // LLM 예상 시간 → 브리핑 속도 계산
  "teams": [                                           // 지연 (LLM)
    { "id", "summary", "verdict":"positive|neutral|negative",
      "tags":[{text,type}], "basis":[{k,v}] }          // basis는 정형 수치(LLM 미경유)
  ],
  "conclusion": {                                      // 지연
    "label":"강세", "positive_count":2, "neutral_count":1, "negative_count":0,
    "summary":"한 줄 종합",
    "scenarios":[ {name, pct, trigger} ],              // 합 100
    "facts": { target_price, upside_pct, opinion, opinion_score, firm_count }
  }
}
```

### 역할 분담
- **즉시 표시:** quote, profit → 시세 카드 + 차트 + 브리핑 + 인트로 멘트 (프론트 계산)
- **브리핑 멘트:** quote/profit으로 **프론트가 생성** (백엔드 문구 X)
- **teams[].summary:** LLM 생성 (§7 카피 원칙 적용)
- **teams[].basis:** 정형 수치 (LLM 미경유)
- **conclusion.label/막대:** teams verdict 집계 (정밀 점수 불필요)
- **llm_eta_sec:** 브리핑 속도 동적 조절용 (캐시면 작게)

## 2. 사용자 여정 — 단계별 목적

## 6. BM 요약

```
딥스캔 (건별)  →  일회성 진단, 크레딧 소모
포트폴리오 워치 (구독)  →  버티는 동안 지속 감시

과금 후보:  A. 포트폴리오 전체 월정액 / C. Pro 통합 (비교표는 BM 문서 §4-B)
무료 체험:  며칠간 전체 개방 → 유료 전환
```

### 사용자 두 유형
| | 유형 1 (계속 봄) | 유형 2 (안 봄) |
|---|---|---|
| 문제 | 정보 과잉, 불안 증폭 | 결정적 순간도 놓침 |
| 워치 역할 | 필터 — 중요한 것만 | 대리 감시 — 대신 봐줌 |
| 파는 것 | 피로 감소 | **안심 (보험 구조)** |

유형 2는 앱을 안 켜도 **구독은 유지** → 리텐션 무관 매출. "안 봐도 된다"를 파는 게 다른 앱이 못 하는 포지션.

### 유인 정렬 (반드시 지킬 것)
- 손절 신호는 정직하게. 팔면 "잘 파셨어요, 다음 종목" 으로 관계 지속
- 종목당 과금(안 B)은 **금지** — 손절이 구독 해지가 되면 버티기 조장 유인 발생

1왜 이 BM인가 — 문제→통찰→전략

문제 — 기존 진단앱의 한계

  • 딥스캔은 일회성 스냅샷. 한 번 진단하면 관계 끝, 재과금 안 됨.
  • 근데 실제 사용자(물린 사람)는 몇 달~몇 년을 버틴다.
  • 이 긴 기다림 동안 계속 불안하지만, 앱은 아무것도 안 해줌.

통찰 — 처분효과(disposition effect)

  • 사람은 오른 건 빨리 팔고, 내린 건 안 판다.
  • 이유: 매도 = 손실 확정 = 실패 인정. 안 팔면 "아직 잃은 거 아냐"로 미룰 수 있음.
  • 결론: 손절을 강요해도 사람들은 안 한다. 이건 바꿀 수 없는 현실.

전략 — 기다림에 올라타기

  • 손절 유도가 목적이 아님. 어차피 버틸 거, 제대로 버티게 해주고 과금.
  • 버티는 시간 = 구독 기간. 일회성 진단 → 지속 구독으로 전환.

§1-B 사용자 두 유형 — BM의 뼈대

유형 1: 계속 쳐다봄  → 불안해서 매일 확인, 뉴스 뒤짐, 정보 과잉
유형 2: 아예 안 봄    → 물린 순간 앱 삭제, 계좌 안 엶, "없는 셈" 회피

유형 2가 처분효과의 더 극단적 형태 — 손실 마주하기가 고통스러우니 안 보는 걸로 회피("계좌를 안 열면 손실도 없는 것 같다" = 타조 효과).

실습 — 두 유형 카드

유형 2가 어렵지만 진짜 기회: 앱을 안 켜도 구독은 유지 → 리텐션(자주 켜는 정도) 무관 매출. "안 봐도 된다"를 파는 게 다른 앱이 못 하는 포지션이에요. 유형 1 구독 = "매일 볼 필요 없게 걸러줌"(피로 감소), 유형 2 구독 = "안 봐도 대신 지켜봄"(회피 보장+안심). 공통 축 = "당신 대신 지켜본다".

2핵심 가치 — "변화가 생기면 먼저 알려준다"

물린 사람의 진짜 공포 = "나빠지고 있는데 나만 모름." 이걸 해소하는 게 구독의 본질이에요. 버티는 시간 순서로 세 가지 얼굴:

실습 — 워치의 세 얼굴

셋은 별개 컨셉이 아니라 한 구독 안의 상황별 대응. 관통하는 축은 "변화 감지 + 선제 알림".

딥스캔(일회성)과의 결정적 차이

딥스캔 (일회성)워치 (구독)
성격그 순간의 스냅샷시간에 걸친 감시
가치"지금 어떤가""바뀌면 먼저 알려줌"
공포 대응—"나만 모름" 해소

"딥스캔 한 번 더 사면 되잖아" 반론의 답: 딥스캔은 변화를 못 잡는다. 워치는 변화를 잡는다.

3무엇을 감지해서 알리나 (트리거)

버티는 사람에게 매일 알림은 피곤해요. 의미 있는 변화에만 알려요.

3-1. 손절 고려 신호 (코치)

  • 펀더멘털 훼손: 영업이익 적자 전환, 부채 급증, 지배구조 리스크
  • 기술적 붕괴: 주요 지지선 이탈, 거래량 동반 하락
  • 알림 예: "OO의 실적이 적자 전환했어요. 버틸 근거가 약해지고 있어요. 다시 볼까요?"

3-2. 본전 근접 / 탈출 기회 (동행자)

  • 본전까지 거리 추적, 근접 시 알림
  • 예: "본전까지 +3%예요. 탈출 여부를 고민할 지점이에요."

3-3. 반등 / 추가매수 기회 (동행자)

  • 저점 반등 신호, 평단 낮출 기회 (신중히 — 물타기 조장 주의)
  • 예: "반등 신호가 보여요. 다만 추가매수는 신중하게 판단하세요."

3-4. 주기적 안심 (파수꾼)

  • 변화 없을 땐 조용히. 대신 주 1회/월 1회 "요약"
  • "이번 주 OO은 버틸 근거 유지 중이에요. 특이사항 없어요."
  • → 아무 일 없어도 구독 가치를 느끼게 (안심도 상품)

설계 원칙: 알림 과다 = 이탈. "변화 있을 때만 + 주기 요약" 조합. 사용자가 알림 종류를 켜고 끌 수 있게.

3-5. 유형 2(회피형) 알림 원칙 — 극도로 섬세하게

  • 평소엔 침묵. 아무 일 없으면 조용히 (유형 1의 "주기 요약"도 유형 2에겐 끌 수 있게)
  • 결정적일 때만 신호. 빈도 최소.
  • "손실" 프레임 금지 → "행동 필요" 프레임: 나쁨 "OO −23% 손실 중" / 좋음 "OO에 지금 확인이 필요한 변화가 생겼어요." (중립, 손실 언급 X)
  • 핵심 조합: "평소 안심시키는 침묵 + 결정적 순간의 조용한 신호". 시끄러우면 도망감.

[홈] 물린 종목 카드 └ "이 종목 지켜보기" → 워치 등록 유도 [워치 대시보드] (신규) ├ 감시 중인 종목 리스트 ├ 각 종목: 상태 라벨 + 본전까지 거리 + 마지막 신호 └ "최근 알림" 타임라인 [알림] 변화 발생 시 푸시 └ 탭하면 → 해당 종목 재진단(딥스캔)으로 [마이페이지] └ 워치 구독 관리 (현재 "준비 중" 자리)

  • 워치 알림 → 딥스캔 재진단 순환 (구독 + 건별 결합 가능)

5-B. 유형 2 도달 전략 — "떠나기 직전에 잡기"

유형 2는 곧 앱을 안 켜요. 그래서 아직 앱을 볼 때(물린 직후) 워치로 전환시켜야 해요:

물린 종목 확인 (아직 볼 때) └ "이 종목, 안 보셔도 저희가 지켜볼게요" → 워치 등록 └ 이후 사용자는 앱 안 켜도 → 구독 유지 + 결정적일 때만 알림
  • 등록 시점 카피: 회피 욕구 인정 — "매번 확인하는 거 힘드시죠. 대신 지켜봐드릴게요."
  • 한 번 등록되면 앱 리텐션과 무관하게 구독 유지 (보험처럼)
  • 무료 체험(첫 종목 무료 감시)이 유형 2 전환에 특히 유효

5-C. 이벤트 처리 3층 — "내 종목과 연관되는가"

층 1 (알림 O)   내 종목 직접 — 실적·공시·수주·증자·대주주 변동
층 2 (기록만)   배경 — 미국장·환율·업황·공급망
                → "SFA반도체 영향: 제한적/긍정적" 으로 번역해 기록
층 3 (차단)     무관 — 테마주·루머·타 업종  → "147건 걸러냈어요"

연관 판정 경로: 직접(내 종목 공시) / 업종(반도체 업황→SFA) / 공급망(삼성 투자→협력사) / 거시(미국 반도체주→내 종목, 영향도 판단)

번역 원칙 — 알림은 항상 종목명으로 시작:

  • 나쁨: "미국 나스닥 3% 급락" (남 얘기, 공포만 유발)
  • 좋음: "SFA반도체에 영향이 있을 수 있어요. 어젯밤 미국 반도체주가 빠졌어요. 영향은 제한적이고, 버틸 근거는 그대로예요."
  • 영향 여부만 알리면 불안만 커짐 → "내 근거는 어떻게 됐나"까지 말해야 안심이 됨

예고: 예정 이벤트는 미리 (D-3 "다음 주 실적이에요"). 예측 가능성이 안심을 줌 — 유형 2가 "그때만 보면 되는구나" 하고 안심.
갱신: 이벤트 발생 시 "버틸 근거 조건 체크리스트" 재채점 → 살아있는 문서가 됨.

실습 — 나쁜 BM vs 좋은 BM

위험: "기다림을 팔면" jaroo가 사용자를 계속 버티게 만들 유인이 생긴다. 사용자가 손절하면 구독이 끊기니까, 앱이 은근히 "더 지켜보세요" 하고 버티기를 부추길 수 있어요. 그러면 처분효과를 악용하는 나쁜 앱이 돼요 (사용자 이익과 충돌).

원칙: "기다림을 파는 게 아니라, 좋은 결정을 판다."

  • 손절 신호는 정직하게. 팔아야 할 때 팔라고 한다
  • 사용자가 손절하면 → "잘 파셨어요, 다음 종목 찾아드릴게요"로 관계 지속
  • 한 종목 손절 = 구독 종료 X. 포트폴리오/다음 종목으로 이어짐 (그래서 과금은 A/C안)

  • 안 파는 마음 부정 안 함: "안 팔고 싶은 마음, 이해해요."
  • 현실은 정확히: "다만 지금 상황은 이래요" (숨기지 않음)
  • 손절 = 선택으로 리프레이밍: "손절은 실패가 아니라 다음 기회를 위한 자금 회수예요."

# Jaroo 포트폴리오 워치 — 구독 BM 설계

작성: 2026-05-28
한 줄: **물린 종목을 계속 지켜보다가, 상황이 바뀌면 먼저 알려주는 월 구독.**

---

## 1. 왜 이 BM인가

### 문제 — 기존 진단앱의 한계
- 딥스캔은 **일회성 스냅샷**. 한 번 진단하면 관계 끝, 재과금 안 됨.
- 근데 실제 사용자(물린 사람)는 **몇 달~몇 년을 버틴다.**
- 이 긴 기다림 동안 계속 불안하지만, 앱은 아무것도 안 해줌.

### 통찰 — 처분효과(disposition effect)
- 사람은 오른 건 빨리 팔고, 내린 건 안 판다.
- 이유: **매도 = 손실 확정 = 실패 인정.** 안 팔면 "아직 잃은 거 아냐"로 미룰 수 있음.
- 결론: **손절을 강요해도 사람들은 안 한다.** 이건 바꿀 수 없는 현실.

### 전략 — 기다림에 올라타기
- 손절 유도가 목적이 아님. 어차피 버틸 거, **제대로 버티게** 해주고 과금.
- 버티는 시간 = 구독 기간. 일회성 진단 → 지속 구독으로 전환.

---

## 1-B. 사용자 두 유형 — 이게 BM의 뼈대

물린 사람은 손실을 대하는 방식이 정반대로 갈린다:

```
유형 1: 계속 쳐다봄  → 불안해서 매일 확인, 뉴스 뒤짐, 정보 과잉
유형 2: 아예 안 봄    → 물린 순간 앱 삭제, 계좌 안 엶, "없는 셈" 회피
```

**유형 2가 처분효과의 더 극단적 형태.** 손실을 마주하는 게 고통스러우니 아예 안 보는 걸로 회피 — "계좌를 안 열면 손실도 없는 것 같다"(타조 효과).

### 워치는 유형별로 다르게 작동한다
| | 유형 1 (계속 봄) | 유형 2 (안 봄) |
|---|---|---|
| 문제 | 정보 과잉, 불안 증폭 | 결정적 순간도 놓침 |
| 워치 역할 | **필터** — 중요한 것만 걸러줌 | **대리 감시** — 대신 봐줌 |
| 파는 것 | 피로 감소 ("매일 안 봐도 됨") | **안심 ("안 봐도 안전")** |

### 유형 2가 어렵지만 진짜 기회인 이유
- **어려움**: 앱을 안 켠다 → 리텐션 0에 수렴. 손실 알림은 더 회피.
- **기회**: 안 보는 사람일수록 "대신 봐주는" 가치가 크다. 그리고 **구독은 앱을 안 켜도 유지된다.**
- → **보험 구조.** 평소 신경 안 써도, 있으면 안심되고, 매달 돈 낸다. 유형 2한테 파는 건 **"안심"** — 손실을 안 봐도 되게 해주면서(회피 충족), 진짜 위험할 때만 조용히 깨운다(최악 방지).

```
유형 1 구독:  "매일 볼 필요 없게 걸러줌"    (피로 감소)
유형 2 구독:  "안 봐도 대신 지켜봄"          (회피 보장 + 안심)
공통 축:      "당신 대신 지켜본다"
```

## 2. 핵심 가치 — "변화가 생기면 먼저 알려준다"

물린 사람의 진짜 공포 = **"나빠지고 있는데 나만 모름."**
이걸 지켜봐주는 게 구독의 본질. 버티는 시간 순서로 세 가지 얼굴:

```
버티는 중   → [파수꾼]  "지금은 버틸 근거 있어요" + 나빠지면 감지
                ↓
신호 발생   → [코치]    "펀더멘털이 깨졌어요, 손절 고민할 시점"
                ↓
회복 국면   → [동행자]  "본전까지 +8% 남았어요" 탈출 기회 추적
```

셋은 별개 컨셉이 아니라 **한 구독 안의 상황별 대응**. 관통하는 축은 "변화 감지 + 선제 알림".

### 딥스캔(일회성)과의 결정적 차이
| | 딥스캔 (일회성) | 워치 (구독) |
|---|---|---|
| 성격 | 그 순간의 스냅샷 | 시간에 걸친 감시 |
| 가치 | "지금 어떤가" | **"바뀌면 먼저 알려줌"** |
| 사용자 공포 대응 | — | "나만 모름"을 해소 |

→ "딥스캔 한 번 더 사면 되잖아"라는 반론의 답: **딥스캔은 변화를 못 잡는다. 워치는 변화를 잡는다.**

## 3. 무엇을 감지해서 알리나 (트리거) — 초안

버티는 사람에게 매일 알림은 피곤함. **의미 있는 변화**에만 알림.

### 3-1. 손절 고려 신호 (코치)
- 펀더멘털 훼손: 영업이익 적자 전환, 부채 급증, 지배구조 리스크
- 기술적 붕괴: 주요 지지선 이탈, 거래량 동반 하락
- 알림 예: "OO의 실적이 적자 전환했어요. 버틸 근거가 약해지고 있어요. 다시 볼까요?"

### 3-2. 본전 근접 / 탈출 기회 (동행자)
- 본전까지 거리 추적, 근접 시 알림
- 알림 예: "본전까지 +3%예요. 탈출 여부를 고민할 지점이에요."

### 3-3. 반등 / 추가매수 기회 (동행자)
- 저점 반등 신호, 평단 낮출 기회 (신중히 — 물타기 조장 주의)
- 알림 예: "반등 신호가 보여요. 다만 추가매수는 신중하게 판단하세요."

### 3-4. 주기적 안심 (파수꾼)
- 변화 없을 땐 조용히. 대신 주 1회/월 1회 "요약"
- "이번 주 OO은 버틸 근거 유지 중이에요. 특이사항 없어요."
- → 아무 일 없어도 구독 가치를 느끼게 (안심도 상품)

**설계 원칙**: 알림 과다 = 이탈. "변화 있을 때만 + 주기 요약" 조합. 사용자가 알림 종류를 켜고 끌 수 있게.

### 3-5. 유형 2(회피형)를 위한 알림 원칙 — 극도로 섬세하게
유형 2는 "손실 알림"을 극도로 싫어함. 잘못하면 알림 끄고 이탈.
- **평소엔 침묵.** 아무 일 없으면 조용히. (유형 1의 "주기 요약"도 유형 2에겐 끌 수 있게)
- **결정적일 때만** 신호. 빈도 최소.
- **"손실" 프레임 금지 → "행동 필요" 프레임.**
  - 나쁨: "OO −23% 손실 중" (보기 싫은 걸 들이밈)
  - 좋음: "OO에 지금 확인이 필요한 변화가 생겼어요." (중립, 손실 언급 X)
- 핵심 조합: **"평소 안심시키는 침묵 + 결정적 순간의 조용한 신호."** 시끄러우면 도망감.

### 3-6. 알림 강도 — 사용자가 직접 고름
유형 1/2를 우리가 추측하지 않고 **사용자가 자기 상태를 고르게** 한다. (사람은 시기에 따라 달라짐 — 고정 유형이 아니라 상태)

| 선택지 | 내용 | 빈도 |
|---|---|---|
| **안 보고 싶어요** | 버틸 근거 깨짐 / 본전 근접만. 주간 요약도 없음 | 월 1~2회 |
| **적당히 알려줘요** (기본) | + 실적·공시, 근거 변화, 주 1회 요약 | 주 1~2회 |
| **다 알고 싶어요** | + 업황·공급망·미국장 영향, 5% 이상 급등락 | 주 3~5회 |

- 이벤트 3층(§7)과 매핑: 최소=층1 핵심 / 보통=층1 전부 / 상세=층1+층2. **층3은 어느 단계에서도 안 감.**
- **안전 하한선**: 거래정지·상장폐지 위험, 버틸 근거 완전 붕괴는 "안 보고 싶어요"에서도 반드시 발송. 끌 수 없음을 화면에 명시 → 안심하고 최소를 고를 수 있게.
- **상황별 자동 제안**: "다음 주 실적 발표예요. 그 주만 늘릴까요? 끝나면 원래대로 돌아가요."
- **종목별 개별 설정은 두지 않음.** 대신 손익 상태 보고 자동 차등(손실 종목 더 챙김, 수익 종목 조용히). 이유: 설정 세분화는 대다수가 안 쓰고, 특히 "안 보고 싶어요"를 고른 사람에게 종목별 설정을 시키는 건 모순.
- **이탈 방지 효과**: 알림이 많아 짜증나면 보통 앱 삭제/알림 전체 차단으로 감. "안 보고 싶어요"라는 중간 선택지가 있으면 **완전 이탈 대신 강도만 낮추고 구독은 유지**.

### 3-7. 실시간 보고서는 만들지 않는다
"매일 종목 보고서 생성"은 세 가지로 실패:
1. **워치의 약속과 충돌** — "안 보셔도 괜찮아요"인데 매일 볼 게 생김
2. **비용 초과** — 딥스캔 1회 = LLM 60초. 3종목 매일이면 월 90회, 구독료를 넘김
3. **쓸 말이 없음** — 대부분의 날은 의미 있는 변화가 없어 공허한 문장을 지어내게 됨 → 신뢰 훼손

**대신 3단 구조:**
| 주기 | 무엇 | LLM |
|---|---|---|
| 매일 | 지표 감시 (본전거리·급락·공시·D-day) | ✗ 계산만 |
| 주 1회 | 주간 요약 ("특이사항 없어요") | ✗ 템플릿 |
| 이벤트 시 | 딥스캔 재분석 + 판단 갱신 | ✓ 실행 |

**감시는 매일, 분석은 이벤트 때만.**

## 4. 과금 모델 — 초안 (선택 필요)

세 가지 안. 각각 장단:

### 안 A — 포트폴리오 전체 월 구독
```
월 정액 → 보유 종목 전부 감시
예: 월 9,900원 (종목 수 무관)
```
- 장점: 단순, 종목 많은 사람에게 유리, 손절해도 다른 종목 계속 관리 → 관계 지속
- 단점: 종목 1개만 물린 사람에겐 비싸 보임

### 안 B — 종목당 월 구독
```
물린 종목 1개당 월정액
예: 종목당 월 2,900원
```
- 장점: 물린 종목만 골라 등록, 진입장벽 낮음
- 단점: 손절하면 그 종목 구독 끝 → **BM이 손절 억제 유인** (위험!)

### 안 C — Pro 등급에 포함
```
Jaroo Pro 월 구독 → 딥스캔 무제한 + 워치 포함
예: 월 4,900원
```
- 장점: 기존 Pro와 통합, 단순한 가격표, 딥스캔+워치 묶음 가치
- 단점: 워치만 원하는 사람에게 과할 수 있음

**추천: 안 A 또는 C.** 안 B는 "종목 손절 = 구독 해지"라 손절 억제 유인이 생겨 위험(§6 참조). 포트폴리오 단위나 Pro 통합이 유인 정렬에 안전.

### 4-B. A vs C 정면 비교 (최종 후보)
| 기준 | A. 포트폴리오 전체 월정액 | C. Pro에 포함 |
|---|---|---|
| 가격 예시 | 월 9,900원 (워치 단독) | 월 4,900원 (딥스캔 무제한+워치) |
| 소비자 인식 | "지켜봐주는 서비스"가 명확 | "다 되는 프리미엄" |
| 유형 2(회피형) 적합 | 높음 — "안심 보험" 딱 맞음 | 중간 — 딥스캔 무제한이 안 보는 사람에겐 잉여 |
| 딥스캔 건별 매출 | 유지됨 (워치와 별개) | 잠식 (무제한이라 건별 소멸) |
| 가격표 복잡도 | 상품 2개(딥스캔 건별 + 워치 구독) | 상품 1개(Pro) — 단순 |
| 확장성 | 워치 티어링 가능(종목 수·감시 강도) | Pro 한 덩어리라 세분화 어려움 |

**판단 포인트**:
- 유형 2("안심 보험")를 주력으로 보면 → **A** (워치를 독립 상품으로, 보험처럼 포지셔닝)
- 단순한 가격표 + 딥스캔 자주 쓰는 헤비유저 묶기 → **C**
- 절충: **A를 기본, Pro는 A+딥스캔무제한 상위 번들**로 두면 둘 다 살림. (워치=보험 독립상품 유지하면서, 헤비유저는 Pro로)

### 4-C. 무료 체험 — 확정
**며칠간 전체 무료 체험** (첫 등록 시 N일 전체 기능 개방 → 이후 유료 전환).
- 유형 2에 특히 유효: 부담 없이 "지켜봐줌"을 경험 → "안 봐도 안전하네" 체감 후 전환.
- 체험 종료 임박 시 알림: "체험이 곧 끝나요. 계속 지켜봐드릴까요?" (회피 욕구 자극 안 하는 중립 톤)
- 체험 기간(N일)은 검증 필요 — 변화가 한 번은 감지될 만큼 길어야 가치 체감(7일? 14일?).

```
[홈] 물린 종목 카드

[알림] 변화 발생 시 푸시
  └ 탭하면 → 해당 종목 재진단(딥스캔)으로

[마이페이지]
  └ 워치 구독 관리 (현재 "준비 중" 자리)
```

- 마이페이지의 Pro 자리가 **포트폴리오 워치 카드**로 교체됨 (지켜보는 종목 수, 다음 확인 시점, 알림 설정 요약, 관리 버튼).
- 홈 종목카드 펼침에 **[딥스캔 분석] [지켜보기]** 나란히 — 손실 종목은 지켜보기 강조.
- 워치 알림 → 딥스캔 재진단으로 이어지는 순환 (구독 + 건별 결합 가능).

### 5-B. 유형 2 도달 전략 — "떠나기 직전에 잡기"
유형 2는 곧 앱을 안 켠다. 그래서 **아직 앱을 볼 때(물린 직후)** 워치로 전환시켜야 함.
```
물린 종목 확인 (아직 볼 때)
  └ "이 종목, 안 보셔도 저희가 지켜볼게요" → 워치 등록
       └ 이후 사용자는 앱 안 켜도 → 구독 유지 + 결정적일 때만 알림
```
- 등록 시점 카피: 회피 욕구를 인정 — "매번 확인하는 거 힘드시죠. 대신 지켜봐드릴게요."
- 한 번 등록되면 앱 리텐션과 무관하게 구독 유지 (보험처럼).
- 무료 체험(첫 종목 무료 감시)이 특히 유형 2 전환에 유효 — 부담 없이 "지켜봐줌"을 경험.

## 5-C. 이벤트 처리 3층 — "내 종목과 연관되는가"

알림 여부의 단일 기준: **내 종목과 연관되는가.**

```
층 1 (알림 O)   내 종목 직접 — 실적·공시·수주·증자·대주주 변동
층 2 (기록만)   배경 — 미국장·환율·업황·공급망
                → "SFA반도체 영향: 제한적/긍정적" 으로 번역해 기록
층 3 (차단)     무관 — 테마주·루머·타 업종  → "147건 걸러냈어요"
```

**연관 판정 경로**: 직접(내 종목 공시) / 업종(반도체 업황→SFA) / 공급망(삼성 투자→협력사) / 거시(미국 반도체주→내 종목, 영향도 판단)

**번역 원칙 — 알림은 항상 종목명으로 시작:**
- 나쁨: "미국 나스닥 3% 급락" (남 얘기, 공포만 유발)
- 좋음: "SFA반도체에 영향이 있을 수 있어요. 어젯밤 미국 반도체주가 빠졌어요. **영향은 제한적이고, 버틸 근거는 그대로예요.**"
- 영향 여부만 알리면 불안만 커짐 → **"내 근거는 어떻게 됐나"까지** 말해야 안심이 됨.

**예고**: 예정 이벤트는 미리 (D-3 "다음 주 실적이에요"). 예측 가능성이 안심을 줌 — 특히 유형 2가 "그때만 보면 되는구나" 하고 안심.

## 6. 유인 정렬 — 반드시 지킬 원칙

**위험: "기다림을 팔면" jaroo가 사용자를 계속 버티게 만들 유인이 생긴다.**
- 사용자가 손절 → 구독 끝 → 매출 끊김
- → jaroo가 은근히 "더 지켜보세요" 하고 **버티기 조장** 가능
- → 처분효과를 **악용**하는 나쁜 앱이 됨 (사용자 이익과 충돌)

**원칙: "기다림을 파는 게 아니라, 좋은 결정을 판다."**
- 손절 신호는 **정직하게** 준다. 팔아야 할 때 팔라고 한다.
- 사용자가 손절하면 → "잘 파셨어요, 다음 종목 찾아드릴게요"로 **관계 지속**
- 한 종목 손절 = 구독 종료 X. 포트폴리오/다음 종목으로 이어짐 (→ 그래서 과금은 §4 A/C안)

```
나쁜 BM:  버틸수록 돈 벎 → 손절 막음 → 사용자 손해
좋은 BM:  좋은 결정마다 돈 벎 → 손절도 매수도 가치 → 사용자 이익과 일치
```

용어 사전 — 어려운 단어 모음

평단 (평균단가)
여러 번 나눠 산 주식의 "평균 산 값". (산 금액 합계) ÷ (주식 수).
본전
내가 산 값(평단). 주가가 본전 위면 이익, 아래면 손실.
손절
손해를 감수하고 파는 것. "손실 확정"이라 심리적으로 어려움.
물타기 (추가매수)
가격이 내렸을 때 더 사서 평단을 낮추는 것. 잘하면 본전 회복이 빨라지지만 못 하면 손실만 커져요. Jaroo는 권하지 않고 수학만 보여줌.
처분효과 (disposition effect)
오른 주식은 빨리 팔고, 내린 주식은 못 파는 인간의 심리. 팔면 "졌다"는 걸 인정하는 기분이어서.
타조 효과
무서운 걸 안 보면 없는 것처럼 느끼는 회피 심리. "계좌를 안 열면 손실도 없는 것 같다."
MTS
증권사가 주는 주식 거래 앱(모바일 트레이딩 시스템). 종목명 표기가 앱마다 달라서 정규화가 필요.
OCR
사진 속 글자를 읽어서 데이터로 바꾸는 기술. 스크린샷 → 종목 목록.
LLM (대규모 언어 모델)
AI 문장 생성기. 딥스캔의 세 팀 분석·종합 결론을 만들어요. 느림(40~60초)이 핵심 제약.
SSE
서버가 먼저 데이터를 밀어주는 통신 방식. 딥스캔처럼 "빠른 것 먼저, 느긋한 것 나중"에 적합.
폴링
클라이언트가 주기적으로 "왔어요?"라고 물어보는 방식. 딥스캔에선 2초 간격 권장.
스냅샷
어느 순간 딱 한 번 찍은 데이터 사진. 딥스캔의 시세는 실시간 갱신이 아니라 시작 시 1회 스냅샷.
딥스캔
종목 하나를 세 팀(AI)이 깊게 분석하는 일회성 진단. 크레딧(횟수)을 소모. 60초 걸림.
워치
물린 종목을 계속 지켜보다 변화가 생기면 알려주는 구독 상품. Jaroo BM의 축.
층 1 / 2 / 3
뉴스 분류: 1=내 종목 직접(알림), 2=배경(기록만), 3=무관(차단).
트리거
"이 조건이 되면 알림"의 기준선. 예: 본전까지 3% 이내 접근.
버틸 근거
"더 들고 있어도 되는 이유" 체크리스트(예: 업황 회복, 목표가 여력, 흑자 전환). 이벤트마다 재채점.
D-day
중요한 일정까지 남은 날 수. "D-6" = 6일 남음.
PER·PBR·ROE
주식이 싼지(밸류), 회사가 돈을 잘 버는지(수익성) 보는 대표 지표. 가치·기본 팀의 근거.
52주 고저
최근 1년 동안 최고가·최저가. "내 자리가 어디쯤인지"와 최악 시나리오 계산에 사용.
수급 (외국인/기관)
누가 사고 파는지 정보. 실시간 데이터가 불가해서 화면·근거에서 제외됨.
디자인 토큰
색·글자 크기 등을 "이름 붙은 값"으로 정해둔 것. 일관성을 지키는 약속.
tabular-nums
숫자 폭을 고정하는 글자 옵션. 시계처럼 숫자가 흔들리지 않게.
U+2212 (−)
진짜 마이너스 부호. 하이픈(-)보다 길이가 숫자와 어울려서 손실 표기에 사용.
유인 정렬
앱이 돈을 버는 방식이 사용자 이익과 같은 방향을 향하게 하는 설계 원칙. 반대로 되면 "버티기 조장" 같은 나쁜 앱이 됨.
리텐션
사용자가 앱을 계속 켜는 정도. 유형 2는 리텐션이 0에 수렴해도 구독은 유지됨(보험 구조).
티어링
상품을 등급(티어)으로 나누는 것. 예: 종목 수·감시 강도별 워치 등급.
크레딧
딥스캔 같은 건별 기능을 쓰기 위한 횟수권. 단가는 아직 미확정.
Pro
월 구독 상품 후보. "딥스캔 무제한 + 워치 포함" 묶음(과금 안 C).
