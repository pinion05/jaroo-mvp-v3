한국과 미국 분석은 어디까지 똑똑해졌을까?

두 시장 모두 재무·가격·컨센서스를 9명의 AI 위원에게 나누어 평가하는 제품 파이프라인이 있습니다. 가장 큰 차이는 공시 원문을 실제로 읽고 해석하는가입니다.

한 문장 결론
일반 분석은 둘 다 제품 수준.
공시 분석은 한국이 약 두 단계 앞섰다.

단, 한국의 5필드 canonical 이벤트 추출기는 아직 연구실 단계이므로 “한국 공시를 완전히 이해한다”는 뜻은 아닙니다.

공통 기반 양쪽 모두 9인 LLM 위원회

한국의 우위 OpenDART 원문 일부를 읽음

중요 공시를 고르고, 긴 문서는 핵심 구간을 잘라 LLM 이벤트 스캐너에 전달합니다.

미국의 현재 한계 SEC 제목·날짜·건수 중심

10-K·8-K·Form 4 목록은 가져오지만 원문/XML의 거래 의미까지 해석하지 않습니다.

쉬운 설명 성숙도 표 파이프라인 LLM 입력 정확도 사용자 체감 최종 판단 코드 근거
01 · 쉬운 설명

학교 신문부로 비유하면

주식 공시는 회사가 공식적으로 제출하는 중요한 문서입니다. 제목만 보는 것과 본문을 읽는 것은 시험에서 목차만 보는 것과 교과서를 읽는 것만큼 차이가 큽니다.

한국 분석
“중요 기사를 골라
본문까지 읽는 기자”

OpenDART에서 공시 목록을 가져오고, 중요도와 위험도를 매긴 뒤 원문을 내려받습니다. 문서가 너무 길면 핵심 부분만 잘라 AI에게 읽힙니다.

“기사 제목과
발행 횟수를 세는 기자”

중요한 공정성 기준

미국 분석 전체가 뒤처진 것은 아닙니다. 가격, 재무, 성장률, 컨센서스, 뉴스, OHLC, 회복 시뮬레이션은 미국도 제품에 연결되어 있습니다. 큰 격차는 “공시 의미 분석” 영역에 집중되어 있습니다.

03 · 구조도

실제 공시 처리 흐름

초록은 현재 운영 경로, 노랑은 제한된 해석, 파랑 점선은 연구 전용, 빨강 점선은 아직 없는 경로입니다.

한국 OpenDART 경로

목록에서 화면까지 이어지는 실제 production path

1. OpenDART 목록 수집종목코드→고유번호, 최근 공시 목록
2. 코드·제목 기반 분류정정, 지분, 자본변동, 위험도, 중요도
3. 중요한 공시 선택중복·관계 공시 정리, 우선순위 부여
4. document.xml 원문 추출긴 문서는 핵심 구간, 전체 6만 자 예산
5. 이벤트 스캐너 LLM구조화 요약+원문 일부를 함께 읽음
6. DeepScan 화면공시 수·위험·정정·자본변동·최신 제목
별도 연구 가지 · 사용자 화면에는 미연결
5필드 canonical event 추출기type / action / state / cause / subjectType · gated.v8

04 · LLM 컨텍스트

AI가 실제로 보는 정보

두 나라 모두 JSON을 LLM에 전달하지만 내용의 깊이가 다릅니다. 아래는 코드 구조를 고등학생이 읽기 쉽게 축약한 예입니다.

한국 이벤트 스캐너구조화 정보 + 제한된 원문
selected: [
  { 제목, 날짜, 중요도, 위험도, dumpPolicy }
]
materialEvents: [ ... ]
risks: [ ... ]
llmDump: {
  includedCount,
  failedCount,
  combinedText: "공시 원문 또는 핵심 구간..."
}

// 기본 최대: 파일당 15,000자, 전체 60,000자
미국 ownership 위원요약 + 메타데이터
directOwnershipFlow: {
  signal: "insider-flow-active",
  counts: { totalDirectEvents: 6 },
  latestDates: { latestEvent: "..." },
  filings: [
    { type, title, filedDate, url }
  ]
}

// 원문·거래 수량·가격·매수/매도 방향 없음
// event-risk 위원은 뉴스·실적·컨센서스를 사용
URL이 들어간다고 원문을 읽는 것은 아닙니다.

현재 LLM 요청에는 웹 탐색 도구가 붙지 않습니다. 따라서 SEC URL을 컨텍스트에 넣어도 LLM은 링크 안의 문서를 스스로 열 수 없습니다.

05 · 검증과 정확도

한국도 아직 “완성”은 아니다

한국 production 공시 흐름과 별개로, 5칸짜리 canonical 사건 객체를 만드는 연구기는 블라인드 감사에서 어려움을 드러냈습니다.

36.2%5필드 전체 정확 일치

본문 확보 138건 중 50건이 골드 사건 집합과 완전히 같았습니다.

58.4%필드 단위 micro 정확도

type·action·state·cause·subjectType를 낱개로 비교한 결과입니다.

92.0%문서 확보율

150건 중 138건의 본문을 안전 제한 안에서 확보했습니다.

0 / 14다중 이벤트 완전 일치

사건이 두 개 이상인 복잡한 공시는 아직 특히 어렵습니다.

이 수치는 “한국 DeepScan 전체 정확도”가 아닙니다.

운영 화면은 현재 별도의 규칙 기반 공시 분류와 LLM 이벤트 스캐너를 사용합니다. 36.2%는 아직 UI에 연결하지 않은 gated.v8 5필드 연구기의 엄격한 계약 일치율입니다. 두 독립 주석자의 5필드 전체 합의율도 79/138(57.2%)라서 문제 자체의 경계가 어렵지만, 이것이 낮은 모델 정확도를 없애주는 것은 아닙니다.

미국 공시 의미 정확도: 측정 불가SEC 공시 본문을 사건으로 해석하는 엔진이 아직 없으므로, 낮은 점수가 아니라 “시험을 아직 만들지 않은 상태”입니다.
06 · 사용자 체감

화면에서 무엇이 달라지나

기술이 코드에만 있는지, 실제 사용자의 판단 화면에 반영되는지를 구분했습니다.

한국 종목을 분석할 때
  • 수익성·밸류·지분안정성·트렌드·이벤트·가격위치 등 9명 위원 결과가 보입니다.
  • 최근 OpenDART 공시 건수, 정정, 자본변동, 고위험 여부가 insight에 반영됩니다.
  • 최근 공시 제목이 근거로 표시되고, 원문 일부가 이벤트 위원의 판단 재료가 됩니다.
아직 안 보이는 것
  • type/action/state/cause/subjectType 5필드 결과는 UI에 표시되지 않습니다.
  • 원문 전체를 그대로 보여주거나 모든 복합 사건을 정확히 분리하지는 못합니다.
미국 종목을 분석할 때
  • 밸류·성장·수익성·모멘텀·추정치 변화·재무안전성 등 9명 위원 결과가 보입니다.
  • 뉴스·컨센서스·OHLC·보유 평단과 회복 전망은 실제 payload와 화면에 반영됩니다.
  • 최근 Form 3/4/5 또는 SC13D/G가 있으면 ownership 공시 건수가 짧게 표시됩니다.
아직 안 보이는 것
  • 10-K·10-Q·8-K 본문에서 추출한 사건·위험 카드가 없습니다.
  • Form 4의 실제 매수/매도, 거래자, 주식 수, 가격을 해석한 설명이 없습니다.
07 · 최종 판단

어디까지 고도화됐나

직접 코드로 확인된 사실과 그 사실에서 도출한 해석을 분리했습니다.

근거가 강한 결론
한국은 “공시를 읽는 제품”, 미국은 “공시 활동을 감지하는 제품”이다.

전체 주식 분석 수준은 양쪽 모두 상당히 높지만, 공시만 떼어 보면 한국은 수집→선별→원문→LLM→UI가 연결됐고 미국은 목록→건수→짧은 신호에 머뭅니다.

판단 신뢰도

높음 · 생산 연결 여부호출 경로, payload, UI projection이 코드로 확인됨
높음 · 미국 본문 미사용SEC collector와 LLM dump 양쪽에서 본문 파서가 없음
중간 · 실제 사용자 품질코드 구조는 확인했지만 운영 텔레메트리·사용자 만족도 자료는 없음
미국이 한국 수준에 도달하려면
  1. SEC primary document와 Form 4 XML을 실제로 다운로드
  2. 8-K item code, Form 4 거래, 10-K/10-Q 위험 요인별 파서 구축
  3. 미국용 사건 schema와 블라인드 정답셋으로 정확도 평가
  4. shadow 실행 후 공시 근거 카드를 UI에 연결
한국이 다음 단계로 가려면
  1. 운영 공시 위험 분류 자체의 블라인드 정확도 별도 측정
  2. 정정·긴 문서·다중 이벤트에서 canonical 추출 정확도 개선
  3. 충분한 정확도와 calibration 확보 전까지 연구 결과를 UI와 분리
  4. 사용자에게 근거 문장과 불확실성을 더 직접적으로 표시
