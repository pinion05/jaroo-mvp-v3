## 1. 측정 기법

- **타임라인 캡처**: 딥스캔 실행 중 페이지 내 샘플러가 **500ms 간격**으로 DOM을 표본화해
  `(t, 경로, 페인팅 스켈레톤 수, DOM 스켈레톤 수, 브리핑 스켈레톤 수, 단계 플래그, 대기 타이머, 팀 등장 인덱스, 내러티브 카드 위치, 본문 다이제스트)`를 기록한다.
  외부 수집기(node 스크립트)가 버퍼를 주기적으로 drain해 JSONL로 남긴다. 전체 새로고침/이탈로 샘플러가 소실되면 즉시 재설치하며 이 시점을 `sampler-lost-nav` 이벤트로 기록한다(이탈·재진입 시나리오의 경계 표식).
- **"페인팅 스켈레톤" 판별**: rect>0 + opacity≠0 + (배경색 알파>0 또는 배경이미지 존재).
  관찰 런에서 종결 후 `todayBriefSkeletonBar` 요소가 DOM에 잔존하되 **투명 배경으로 실제로는 그려지지 않는** 사례가 확인되어, DOM 잔존(`skDom`)과 시각 노출(`skPainted`)을 분리 계상한다. 필요 시 뷰포트 스크린샷 픽셀 검증으로 보조 확정했다.
- **팀 카드 순서**: 본문 텍스트에서 세 팀명의 등장 인덱스(문서 순서=블록 레이아웃 시각 순서)와 `narrativeCard` 위치(y)를 병행 기록해 재정렬 점프를 검출한다.
- **런 구성**: ①정상 런(`run-normal`) ②교란 런(`run-abandon`, 시작 5초 후 이탈→재진입 — 최종 구현은 홈 SPA 이탈 후 /deepscan 재진입; 초기의 새로고침 이탈은 측정 하네스를 붕괴시켜(한계 5) 순수 CDP 보조 재현으로 대체). agent-browser가 네트워크 스로틀링을 지원하지 않는 것을 확인(`network` 그룹은 route/HAR만 제공)하여, 지시에 따라 '느린 네트워크' 대신 **이탈→재진입 교란**으로 대체했다.
- **종결 판정**: 상단 "상세 결과 준비 완료" + 세 팀 카드 모두 등장 + "요약 완료" 3회 + 바닥 문구 도달. 종결 감지 후 15초 추가 관찰로 잔존 로딩 요소를 포착한다.

## 4. TC 상세

### TC-BBSC-001 스켈레톤 대기

- **목적**: 실제 콘텐츠(브리핑 수치, 팀 카드)가 도착하기 전 해당 영역이 비어 있지 않고 스켈레톤/플레이스홀더로 점유하는가. 빈 공백·깜빡임 점프가 없는가.
- **절차**: `run-normal` 타임라인에서 각 단계(가격 위치, 팀1~3) 첫 등장 직전 ~3초(6표본) 창의 페인팅 스켈레톤 존재 여부 집계. 보조: 오늘 장 브리핑 Q&A(`todayBriefSkeleton` 계열) 등장·성장 시점과 답변 텍스트 도착 시점 대조.
- **기대값 출처**: ② 일반 UX 관행, ③ 관찰 런(브리핑 Q&A 영역이 `todayBriefSkeleton`으로 점유 후 교체됨).
- **결과** (증거: `run-normal-20261109T151444.jsonl`):
  - 팀1(시장·차트) 첫 등장 30.6s — 직전 6/6 표본 스켈레톤 점유
  - 팀2·팀3 첫 등장 51.6s — 직전 6/6 표본 스켈레톤 점유
  - 가격 위치 블록("오늘 장 기준" 현재가·차트)은 **첫 페인트와 동시 도착**(4.7s, 딥스캔 화면 첫 표본부터 존재) — 대기 창 자체가 없음. 빈 공백 노출 구간 없음(스켈레톤 불필요 관행 케이스)
  - 브리핑 Q&A 7개 항목: 질문+대부분 답변이 초기 페인트에 도착, "애널리스트 목표가" 항목은 질문(5.1s)→답변(43.1s) 사이 `todayBriefSkeleton` 계열이 10.1s부터 21개까지 성장하며 점유 — 답변 대기 중 공백 없음
- **판정**: **PASS** — 도착이 늦은 모든 영역(팀 카드, 목표가 답변)은 스켈레톤이 선행 점유. 즉시 도착한 영역은 공백 노출 없음.

### TC-BBSC-002 공개 순서

- **목적**: 안내 문구가 소개한 순서(가격 위치→핵심 근거→세 팀 판단, "세 분석가가 차례로")대로 콘텐츠가 공개되는가. 타임라인 역전·동시 점프 확인.
- **절차**: `run-normal` 타임라인에서 `오늘 장 기준`(가격 위치)·`시세는 다 봤어요`(근거 단계 완료 안내)·세 팀 카드 첫 등장 시각 순서 비교.
- **기대값 출처**: ① 제품 안내 문구(/deepscan 대기 화면), ③ 관찰 런.
- **결과** (증거: 동일): 관측 순서 = 가격 위치(4.7s) → 근거 완료 안내(4.7s, 동일 표본) → 팀1 시장·차트(30.6s) → 팀2 심리·환경(51.6s) + 팀3 가치·기본(51.6s). **역전 0건**. 팀2·팀3은 같은 500ms 표본 내 도착으로 상호 순서는 측정 해상도 밖(문서 순서는 팀1→팀2→팀3으로 안정).
- **판정**: **PASS** (부기: 안내 순서 준수. 상단 종결 문구 "상세 결과 준비 완료"가 30.6s에 표시되어 팀2·3 완료(51.6s)보다 앞섰는데, 이 문구는 브리핑(상세 결과) 도착을 알리는 것으로 문맥상 구분됨 — 다만 사용자 오해 여지로 5절 이상 목록에 기록)

### TC-BBSC-003 타이밍 적절성

- **목적**: 단계 공개 간격이 사용자 방치(동일 스켈레톤 60초+ 정체) 없이 진행되는가. 완료된 콘텐츠가 다시 스켈레톤으로 회귀하지 않는가.
- **절차**: 정체 검출(동일 상태≥60s), 플래그 회귀 검출(도착 후 소실→재등장), 전 단계 도착 후 페인팅 스켈레톤 재발생 검출.
- **기대값 출처**: ② 관행. 보조: 상단 대기 타이머("분석가 응답을 기다리는 중… mm:ss")가 진행 피드백을 제공하는지 관찰.
- **결과**: 정체 0건(최대 단계 간격 팀1→팀2/3 21.0초, 60초 임계 미달). 플래그 회귀 0건(가격 위치·근거·팀1~3·요약완료 배지 카운트 단조 증가 — 감소 0회). 도착 후 스켈레톤 "재점거"는 TC-BBSC-005의 종결 후 잔존(DOM 유지)과 동일한 현상으로, 콘텐츠 ↔ 스켈레톤 깜빡임 교차는 없었음. 대기 중 상단 타이머 00:00→00:25 진행 피드백 상존.
- **판정**: **PASS**

### TC-BBSC-004 팀 도착 순서와 무관한 그리드 안정성

- **목적**: 팀 카드가 도착 순서와 무관하게 배치가 안정적인가. 재정렬 점프(기존 카드가 밀리는 레이아웃 점프) 관찰.
- **절차**: 타임라인에서 세 팀명의 본문 등장 인덱스 순서 + `narrativeCard` y좌표 순서 변화 추적.
- **기대값 출처**: ② 관행(완성된 카드의 자리 이동 금지), ③ 관찰 런.
- **결과**: 순서 키 변화 1회 검출 — `t1` → `t1>t2>t3`(51.6s). 이는 팀2·3 **신규 도착**에 따른 키 확장이며 기존 팀1 카드의 문서 인덱스·위치 역전은 없었음(재배치 0건). 종결 시점 문서 순서 팀1→팀2→팀3 유지.
- **판정**: **PASS**

### TC-BBSC-005 종결 경로

- **목적**: 최종 결과로 넘어갈 때 로딩 요소가 전부 소거되는가. 종결 후 잔여 스켈레톤/로딩 문구가 없는가.
- **절차**: 종결 감지 후 15초 관찰 구간에서 ① 페인팅 스켈레톤 표본 수 ② DOM 잔존 스켈레톤 ③ "기다리는 중" 라벨·타이머 잔존 ④ "세 팀이 의견을 정리하는 중…" 라벨 잔존 확인. 필요 시 픽셀 검증.
- **기대값 출처**: ② 관행(종결 후 로딩 소거), ① 제품 종결 문구("상세 결과 준비 완료·실제 응답이 도착했어요").
- **결과**:
  - 소거된 것: 상단 "분석가 응답을 기다리는 중…" 라벨+타이머 소멸 ✓, "상세 결과 준비 완료"로 전환 ✓
  - **잔존 ①(텍스트 로딩 라벨)**: "세 팀이 의견을 정리하는 중…" 라벨이 세 팀 모두 "요약 완료"·종결 감지 이후에도 잔존 — 종결 후 33/33 표본 연속 관측(플래그), 픽셀 검증(관찰 런, 정확 좌표 369 텍스트 픽셀 렌더링 확인)
  - **잔존 ②(DOM 스켈레톤)**: `todayBriefSkeleton`/`todayBriefSkeletonBar` 22개가 DOM에 잔존(스타일상 회색 그라디언트 배경 보유). 단 뷰포트 스크린샷 픽셀 검증(상단·중간 2개 스크롤 위치, 콘텐츠 컬럼 그레이 밴드 스캔)에서 실제 회색 바 렌더링 픽셀 미검출 — 답변 콘텐츠가 위에 덮여 시각적으로는 은폐된 상태. 잔존 자체는 비용(메모리·의미)이나 사용자 가시 결함은 아니라고 판단
  - 종결 판정 자체는 명확: readyTop+footer+요약완료 4회+세 팀 카드 동시 성립(51.6s)
- **판정**: **FAIL — 제품 결함**(원인 판정: 제품 결함. 종결 후 로딩 상태를 나타내는 문구가 소거되지 않음. TC 기대값 오류 아님 — ② 관행·① 제품 종결 문구와 모순)

### TC-BBSC-006 캐시 즉시 열람("다시 보기")

- **목적**: 기록 "다시 보기"가 스켈레톤 없이(혹은 아주 짧게) 즉시 결과를 여는가.
- **절차**: `cache-replay` — 기록 탭 → "다시 보기" 클릭 → 첫 콘텐츠 도달 시간·페인팅 스켈레톤 표본 수 측정.
- **기대값 출처**: ② 관행(캐시된 결과는 즉시), 판정 창 ≤2초/스켈레톤 ≤1초.
- **결과**: 측정 시간대(2026-11-09 14:54~16:40) 내내 `/api/deepscan/history`·`/api/etf/history`가 **503**을 반환하며 기록 탭이 에러 카드("기록을 불러오지 못했어요. 잠시 후 다시 시도해주세요.")만 노출 — "다시 보기" 진입점 자체가 존재하지 않았음. 오늘 배포된 캐시 즉시 열람 동작은 dev에서 검증 불가.
- **판정**: **SKIP(환경 제약)** — 원인 판정: 환경 제약(기록 API 장애). TC 폐기 아님 — API 회복 후 `cache-replay` 재실행 권장. 부기: 기록 탭 에러 카드는 무한 재시도 루프 없이 안내 문구로 정적 노출됨(사용자 방치 상태는 아님).

### TC-BBSC-007 이탈·재진입 내성

- **목적**: 런 중 새로고침/이탈했다 재진입 시 안무가 깨지지 않는가. 오류 카드·무한 대기·빈 결과가 없는가. (과거 "결과를 영원히 숨기는" 버그 계열 회귀 검증)
- **절차**: 세 경로로 분리 측정.
  - (a) 런 중 SPA 이탈(홈 하단 탭 이동)→홈 상태 확인 — `run-abandon` B4 증거 + 순수 CDP A1
  - (b) 런 완료 후 신규 탭 /deepscan 재진입 — 순수 CDP 규격 재현(`suppl-repro-wedge.py` → `reenter-wedge-repro.json`)
  - (c) **런 진행 중(+8초) F5 새로고침** — 순수 CDP 규격 재현(`suppl-f5-test.py` → `f5-midrun-wedge.json`). agent-browser가 특정 순간 불안정(아래 한계 5)하여, 판정 재현은 agent-browser를 완전히 배제한 원시 CDP(전용 Chrome+websockets)로 수행했다.
- **기대값 출처**: ② 관행, ① 제품 안내("완료 신호가 오면 기다림 없이 이 화면 아래에 결과가 이어집니다").
- **결과**:
  - **(a) 런 중 SPA 이탈 → 정상.** 홈은 오류 카드 없이 정상 렌더, 세션·포트폴리오 유지("abandon-left-state" B4, 순수 CDP `A1 left(home): u=/home err=False`).
  - **(b) 완료 후 재진입 → 동작은 하나 결과 미보존.** 신규 탭 /deepscan 직접 접속은 즉시 로드(평가 지연 1~2ms, 90초 관찰 RSS 548MB 일정 — 웨지 없음)되지만 **"분석할 종목이 없습니다" 빈 대기 상태**만 표시. 완료된 런의 결과는 URL로 복원되지 않는다(재열람은 기록 탭 경로인데 TC-006 제약으로 불가).
  - **(c) 런 진행 중 F5 → 페이지 웨지+메모리 폭발 (재현 확정).** 새로고침 10초 후부터 120초 관찰 종료까지 **모든 페이지 평가 타임아웃**(6초+ 12/12표본), 렌더러 CPU 40~70% 급등, **RSS 30초 만에 1.8GB→3.7GB** 폭발 후 비회수. 사전 관찰에서는 동일 상태가 25분+ 지속(RSS 3.5GB, CPU 19%)하며 머신(30GB) 메모리를 고갈시켰다. 사용자 관점: 딥스캔 분석 중 새로고침·북마크 재진입 시 탭이 영구 응답 불능 — **결과를 영원히 볼 수 없다**. 모바일(MTS 스크린샷 서비스 특성상 주 사용 환경)에서는 탭 OOM 종료로 이어질 규모.
  - 경로 (c)는 6회의 우발 관측(14:52 최초, B3 reload, B4 reenter, 격리 F5 2회, 런 중 자발 소멸 1회) 후 원인을 하네스(agent-browser 데몬)와 제품으로 분리·규격 재현으로 확정했다. 우발 관측 당시 agent-browser 데몬 불안정(tab 소멸·세션 롤백)이 함께 나타났으나, 순수 CDP 재현에서 탭 소멸 없이 페이지만 웨지되므로 **탭 소멸·게스트 롤백은 측정 하네스의 파생 증상**이고 **페이지 웨지+메모리 폭발이 제품 결함**이다.
- **판정**: **FAIL — 제품 결함**(딥스캔 런 진행 중 문서 새로고침/재진입 경로의 치명적 결함. 원인 판정 근거: agent-browser 무개입 순수 CDP에서 2회 재현, 조건 대조(완료 후 재진입·SPA 이탈은 정상)로 트리거 특정)

## 5. 타임라인 이상 목록

1. **[제품 결함 확정 — 치명적] 딥스캔 런 진행 중 문서 새로고침/직접 재진입 시 페이지 웨지+메모리 폭발** — 렌더러 CPU 40~70%, RSS 30초 만에 1.8→3.7GB, 평가 전면 불응(회복 없음, 25분+ 관측). 순수 CDP 2회 재현. → TC-BBSC-007 FAIL. 완료 후 재진입은 정상(빈 상태), SPA 이탈은 정상 — 트리거는 "런 활성 상태에서의 전체 문서 로드"로 특정됨.
2. **[제품 결함 확정] 종결 후 로딩 라벨 잔존** — "세 팀이 의견을 정리하는 중…" 라벨(팀 섹션 상단)이 세 팀 모두 "요약 완료"가 된 뒤에도 소거되지 않고 잔존. 정확 좌표 픽셀 검증으로 실제 렌더링 확인(관찰 런), `run-normal` 종결 후 33/33 표본 연속 잔존. → TC-BBSC-005 FAIL
3. **[관찰] 완료된 런 결과의 URL 미보존** — 런 종결 후 /deepscan 재접속은 항상 "분석할 종목이 없습니다" 빈 상태. 결과 재열람 경로는 기록 탭뿐인데 당일 API 장애로 검증 불가(TC-006 SKIP). 설계 의도 여부는 블랙박스로 판단 불가 — 기록 탭 회복 시 "다시 보기" 동작 확인 권장.
4. **[관찰] 종결 문구 조기 표시** — 상단 "상세 결과 준비 완료" 전환이 30.6s, 팀2·팀3 카드 완료는 51.6s. 약 21초간 "준비 완료" 문구와 미완료 팀이 공존. 문구가 브리핑(상세 결과) 도착을 알리는 것이라 의도일 수 있으나, 로딩 중 "완료" 문구와 진행 중 콘텐츠의 공존은 사용자 오해 여지 있음.
5. **[관찰] 종결 후 DOM 스켈레톤 미회수** — `todayBriefSkeleton`/`todayBriefSkeletonBar` 22개가 종결 후에도 DOM에 잔존(스타일상 불투명 회색 그라디언트 보유). 픽셀 검증 결과 답변 콘텐츠가 덮어 시각 노출은 없음 — 가시 결함은 아니나 요소 회수 누수로 보임.
6. **[환경 제약] 기록 탭 전체 불가** — `/api/deepscan/history`·`/api/etf/history` 503(측정 시간 내내). → TC-BBSC-006 SKIP.
7. **[환경 제약] 포트폴리오 유실 재현** — `/api/portfolio` GET 500(`load-failed`) 산발. 홈이 "포트폴리오 준비" 빈 상태로 보임. 스크린샷 재업로드(POST 200)로 회복. 딥스캔 안무 자체와는 무관하나 진입 준비 절차의 변동성으로 기록.
8. **[관찰] 런 초기 무스켈레톤 구간** — 딥스캔 첫 페인트~약 5초간 스켈레톤 0(상단 대기 타이머만 존재). 브리핑 콘텐츠가 초기 페인트와 동시 도착해 공백 노출은 아님(관행상 문제 없음). 이후 목표가 답변 등 지연 항목은 스켈레톤 점유 확인.

## 6. 측정 기법의 한계

1. **표본 해상도 500ms** — 500ms 미만의 순서 차·깜빡임은 검출 못함. 실측에서도 팀2·팀3가 동일 표본에 도착해 상호 순서 미분별(문서 순서는 안정적으로 팀1→2→3).
2. **"페인팅 스켈레톤" 판별의 간접성** — computed style(rect·opacity·배경) 기반이라 위에 덮인 요소를 false-positive로 계상할 수 있음. 실제로 `todayBriefSkeletonBar`가 스타일상 불투명 배경인데 픽셀상 미그림인 사례 발생. 보정 수단으로 뷰포트 스크린샷 픽셀 검증을 수행했으나 전 페이지 스크롤 위치를 전수 스캔하지는 못함(상단+중간 2~3개 위치).
3. **이미지 판독 모델 부재** — 본 측정 에이전트는 스크린샷을 이미지로 읽지 못하는 모델이어서 사람 눈 등가 검증 대신 픽셀 통계(그레이 밴드·텍스트 픽셀 수)로 판정했다. 색상·모양 기반 휴리스틱이므로 미묘한 시각 결함 놓침 가능.
4. **네트워크 스로틀링 불가** — agent-browser가 조절을 지원하지 않아(route/HAR만 제공) '느린 네트워크' 런이 없음. 이탈→재진입 교란으로 대체(지시 승인된 대체안).
5. **측정 하네스(agent-browser) 불안정 — 원인 규명 완료**: ① 이 머신 PATH에 agent-browser **0.26.0**(npm-global)과 **0.27.0**(/usr/local→~/.local)이 공존, 서로 다른 호출자가 공유 데몬을 버전 미스매치 재시작시켜 세션 쿠키가 과거 스냅숏(게스트)으로 롤백되는 현상. ② 위 결함 1의 웨지 페이지가 데몬 브라우저에 남으면 CDP 대상 열거 자체가 걸려 데몬 전체가 "busy" 상태가 됨(30분+ 관측). 측정 중 6회 사고(런 중 eval 유실, 탭 소멸, 세션 롤백 포함)는 모두 이 조합으로 설명되며, 제품 결함과의 분리는 순수 CDP(전용 Chrome+websockets, agent-browser 무개입) 재현으로 확정했다. 탭 소멸·게스트 롤백 자체는 하네스 파생 증상으로 판정.
6. **토큰 기반 검출의 결합도** — 단계 검출이 제품 문구(예: "상세 결과 준비 완료")에 의존하므로 문구 변경 시 TC 재조정 필요. CSS Modules 해시 대응으로 클래스 부분일치를 쓰지만 클래스명 자체 변경에는 취약.
7. **SPA 전환 경계** — 라우트 전환 순간 pathname 갱신 지연으로 런 시작 경계에 ±0.5초 오차(관찰: /deepscan 로딩 화면 텍스트가 pathname=/home인 표본에서 포착된 사례 1회).
8. **외부 수집기 drain 주기(1.5초)** — 타임스탬프는 페이지 내 시계(performance.now/Date.now)로 찍히므로 타이밍 정밀도는 샘플러 주기(500ms)에만 의존하고 drain 주기의 영향은 없음. 단, 새로고침 직전 마지막 버퍼는 drain 전에 소실 가능(최대 1.5초 공백).
9. **웨지 재현의 관찰 창** — F5 웨지 재현은 120초(+사전 25분 우발 관측 1회) 관찰이다. 메모리 상한(수렴 여부)·최종 OOM 도달 시간은 끝까지 관측하지 않았다(머신 보호를 위해 강제 종료).
