# TC — 블랙박스 기능 테스트: 인증 상태 사용자 여정 (TC-BBF)

- 작성: 2026-11-05 (블랙박스 TC 담당: bb-functional)
- 산출 스크립트: `scripts/blackbox-auth-journeys.cjs` (실행 방법은 문서 하단)
- 대상 문서 범위: 인증 기능 여정 영역 (운영 jaroo.kr parity는 별도 담당)

## 1. 테스트 원칙 (블랙박스)

- 제품 소스/내부 문서(`src/`, `packages/`, `tests/`, `scripts/` 기존 파일, `docs/`)를 **열람하지 않았다**.
- 관찰 수단은 두 가지뿐:
  1. **브라우저 조작** — `agent-browser` CLI (세션 `jaroo-bb-func`, DevTools 수준의 DOM/이벤트/네트워크 로그 관찰 포함)
  2. **사용자 관점 HTTP 요청** — 브라우저·curl·Node fetch (리다이렉트 수동 추적, 응답 헤더 확인)
- 기대값 출처 체계 (각 TC에 명시):
  - **① 제품 공개 문구**: 화면에 렌더된 문구, 서비스 이용약관/개인정보처리방침 전문
  - **② 공개 법령 지식**: PIPA(만 14세 미만 동의 무효, 동의 전 열람), 전자상거래법(약관 게시), 투자 참고용 고지 관행
  - **③ 일반 UX/보안 관행**: 가드+목적지 보존, 진행 피드백, 실패의 인지 가능성, 보안 헤더(OWASP)
  - **④ 크로스환경 일관성**: 동일 서비스의 로컬/dev 배포 간 동일 동작 기대
  - **⑤ 사용자 목적 상식**: "로그인하면 내 포트폴리오가 보여야 한다" 등

## 5. 상세 여정

### TC-BBF-001 원클릭 로그인 → 홈 도달
- **사전조건**: 게스트로 /login 접근. 로컬은 진짜 Google OAuth로 넘어가 세션 생성 불가(환경 제약) → jaroo-dev에서 실행.
- **단계**: /login 오픈 → 필수 동의 체크 → "Google로 시작하기" 활성화 확인 → 클릭 → 이동/세션 관찰 → /home 진입 관찰.
- **기대결과**: 클릭만으로 세션이 발급되고 홈(포트폴리오 화면)에 진입한다. 로그인 사용자의 홈에는 게스트 배지/로그인 유도가 없어야 한다. [출처 ⑤ + ① "포트폴리오 준비: 로그인하거나 스크린샷을 추가해서…"는 게스트 전용 문구]
- **실제 관찰(jaroo-dev)**: 마우스 클릭 → 자동로그인 즉시 수행 → `/home` 이동. `/api/auth/me`: `authScope=authenticated, provider=supabase-email-password, email=qa-auto@dev.jaroo.kr`. 홈 상단에 이메일 표시, "게스트" 배지 없음. 초기 홈은 보유 종목이 없어 "포트폴리오 준비" 상태(게스트 화면과 동일 안내) → **게스트와의 차이는 헤더(이메일/게스트 배지)로 식별됨**.
- **실제 관찰(로컬)**: 동일 클릭 → `accounts.google.com`(Supabase PKCE, redirect_uri=hrfpnawmlcoaygipulpm.supabase.co)로 이동. 세션 미발급.
- **판정**: jaroo-dev **PASS** / 로컬 **SKIP(환경 제약 — 진짜 구글 OAuth로 넘어감, 우회 금지 규칙 적용, Lead 보고 완료)**

### TC-BBF-002 로그인 입력 게이팅(필수 동의)
- **사전조건**: 게스트, /login.
- **단계**: 동의 체크 전 버튼 상태 수집 → "만 14세 이상이며 서비스 이용약관과 개인정보처리방침에 동의해요" 체크 → 버튼 상태 재수집.
- **기대결과**: 체크 전 이메일/Google/카카오 버튼 비활성화, 체크 후 활성화. Apple은 "준비 중" 비활성 유지. [출처 ② PIPA 만 14세 동의 규정 + ① 제품 문구 "필수"]
- **실제 관찰(로컬)**: 체크 전 3개 버튼 `disabled` → 체크 후 활성화. Apple "준비 중" 유지. 게스트 동의 문구·약관/개인정보 링크 표시. **PASS**
- **실제 관찰(jaroo-dev)**: **체크 전부터** 이메일/Google/카카오 버튼 모두 활성화(동의 없이 로그인 진행 가능 — 실제로 동의 없이 자동로그인 성공). 동의 문구 자체는 표시됨. **FAIL**
- **판정**: 로컬 PASS / jaroo-dev **FAIL** — dev 배포에서 법정 동의 수집이 우회됨(dev 전용 메커니즘으로 안내받았으나, 동의 없이 가입 경로가 열려 있는 상태 그 자체가 관찰됨. 운영(jaroo.kr)에서는 게이팅이 강제되는지 parity 확인 필요)

### TC-BBF-003 게스트 라우트 가드(로그인 필요 화면 보호)
- **사전조건**: 게스트(세션 쿠키 없음).
- **단계**: `/home` `/screenshot` `/terms` `/privacy` `/deepscan` `/mypage` `/mypage/settings` HTTP 접근(리다이렉트 수동 추적) + 브라우저로 `/deepscan` 접근.
- **기대결과**: 개인 영역은 `/login?next=<원래경로>`로 307 리다이렉트하며 목적지를 보존하고, 공개 영역은 200으로 열려 있다. [출처 ③ 인가 가드+목적지 보존 관행, ④ 환경 일관성]
- **실제 관찰(양 환경 동일)**:
  - `/home` `/screenshot` `/terms` `/privacy` → 200
  - `/deepscan` → 307 `/login?next=%2Fdeepscan`, `/mypage` → 307 `/login?next=%2Fmypage`, `/mypage/settings` → 307 `/login?next=%2Fmypage%2Fsettings`
  - 브라우저에서도 동일하게 가드 바운스 확인. `/ocr`은 `/screenshot`으로 리다이렉트되는 별칭 라우트(200).
  - 게스트 `/api/auth/me` 응답: `{"authScope":"guest", ...}` — 게스트 상태 머신이 서버에 존재.
- **판정**: 양 환경 **PASS**
