## 0. v2 전면 수정 요약 (조율 기록)

| 항목 | v1 | v2 (확정) |
|---|---|---|
| 딥스캔의 역할 | 매수 게이트(45/50/55)·매도 라인의 **정적 판단함수** | 페르소나에게 실리는 **"조언"(가중치)**. hero 점수 + 세 팀 요약 3청크 |
| 결정 주체 | 룰엔진(D7: 룰이 결정, LLM은 서사) | **⑤ 매매 결정 턴 = 페르소나 LLM이 능동 결정** (prefix 캐시 활용). D7 개정 |
| 보유종목 평가 | 별도 리뷰 페이즈(M2 sell-first 분기) | **통합 파이프라인** — 매수 모드는 보유 0개의 특수사례. 스캔 집합 = 흥미종목 ∪ 보유종목 |
| 보유종목 가시성 | 덤프 밖 | **①덤프에 보유 섹션 포함** + ②흥미 선정 절차가 심사 (관심 소멸도 명시적 산출) |
| 관심 소멸한 보유종목 | – | **매턴 스캔 유지(Q8-a)** — 매도 심사도 조언 기반으로 통일 |
| 매수 사이징 | entrySizingPct 규칙 | LLM이 **금액 의사(amountKrw)**만 출력 → 실행 계층이 수량 치환 |
| 잔고 초과 매수 | 거부(insufficient_cash) | **가용잔고 전액 기준 수량 강제 다운그레이드** (paper-trade `fit` 모드, §6) |
| 매도 트리거 | 3종 정적 라벨(테제/밴드/목표) | **LLM 판단이 유일한 매매 발생 경로** — 계좌보호 밴드(손절/익절 강제)·날짜 규칙(당일 재매수 금지 등) 전부 폐지 (2026-11-19 확정) |

위원회 9인(딥스캔) 내부 파이프라인은 **건드리지 않는다 — 추상화된 하나의 함수**로 취급. AI 트레이더 쪽 계약은 경계 덤프(요청 파라미터 + 응답 리포트 스냅샷 + scan id)만.

## 1. 문제 정의 — 원턴 루프의 5가지 비결정성

| # | 결정 | 현재 상태 | 트레이더가 되려면 |
|---|---|---|---|
| G1 | **언제 파는가** | 계좌보호 밴드만 존재. "살 때의 이유가 사라지면 판다"가 없음 | 진입 테제 추적 + 조언·소스이탈 종합 매도 심사 |
| G2 | **기억이 판단에 개입** | 메모리는 일기 콘텐츠 전용 | 기억 라인이 ⑤ 결정 꼬리에 주입되어 판단에 개입 |
| G3 | **일지의 연속성** | 실행마다 새로 생성, 어제 일기와 서로 모름 | 과거 일기·기억 주입 + 원장 정합 |
| G4 | **턴의 정의** | 수동 스크립트, 재시작 시 중복 위험 | 영업일 1회 세션 상태머신 + 멱등 |
| G5 | **정적 임계값의 취약성** (v2 신설) | hero 점수 ±3 확률성 → 임계 컷은 48사고 44팔고 오실레이션 | 컷 비교 자체를 폐지 — LLM이 점수를 문맥으로 해석 |

핵심 관점: **매수는 발굴의 끝이 아니라 테제의 시작**이며, **딥스캔은 자문위원, 페르소나는 결정자**다.

## 2. 핵심 결정 사항 (M1~M9 — D1~D10 계승, D7 개정)

| # | 결정 | 내용 |
|---|---|---|
| M1 | **턴 = 호출 1회 = 세션** | 턴은 호출 단위다 — '당일' 같은 날짜 개념은 시스템에 존재하지 않고, 스케줄(예: 영업일 1회)은 운영 기본값일 뿐 판단 규칙이 아니다(2026-11-19 확정). `trading_sessions` 상태머신이 단계 기록 — 재시작은 미완료 phase부터 재개(멱등) |
| M2 | **통합 파이프라인** | 매수 모드 = 보유 0개의 특수사례. 같은 경로: 덤프(+보유 섹션) → 흥미 선정 → 스캔(흥미∪보유) → 결정 → 실행. 매도 우선은 ⑤ 결정 턴 내 정렬(sell-first)로만 표현 |
| M3 | **테제 = 진입 근거 + 무효화 조건** | 매수 판단 로그가 곧 테제 원본(D9 승계). `invalidation`·`recheck_period` 구조적 기록. 테제 원문은 보유 섹션·⑤ 꼬리에 재주입되어 LLM이 심사 |
| M4 | **딥스캔 = 조언(가중치)** | 리포트에서 **hero 점수 + 세 팀 요약 3청크**(시장·차트/심리·환경/가치·기본 — 웹 UI `TEAM_PRESENTATION_ORDER`와 동일 아티팩트, 팀 요약은 스냅샷에 영속화됨)만 꼬리에 실음. "이것은 조언이다. 최종 결정은 당신이다" 고지. 전문은 경계 덤프로 저장만 |
| M5 | **⑤ 매매 결정 턴 = 페르소나 LLM** (D7 개정) | **룰엔진은 결정하지 않는다 — 가드레일 집행·실행 치환만. 결정+서사는 페르소나 LLM이 한 몸으로 출력.** [시스템+덤프] prefix를 ②흥미 선정 턴과 바이트 동일하게 재사용(캐시 hit, 입력비용 ~1/50) |
| M6 | **보유종목은 덤프 안에** | 보유 섹션: 종목·보유기간·평단·현재가·손익 + 진입 근거 요약 + 오늘 소스 증거. ②흥미 선정이 신규/재확인/**소멸**을 명시 출력. 소멸해도 매턴 스캔(Q8-a) |
| M7 | **가드레일 = 물리 제약만** | 단가=실행 시점 시가 고정, 수량=`fit` 치환(§6), 잔고·보유수량 상한. **밴드 강제 매도 없음 — 매매는 오직 LLM 판단에서 발생**(2026-11-19 확정). LLM 위반 시도는 거부+로그. LLM은 단가·수량 계산에서 완전 배제 |
| M8 | **일기·기억은 다중턴 서사** | 일기 프롬프트: 최근 일기 3~5건 + 기억(digest→episodic) 주입(§8). 기억 요약 몇 줄은 ⑤ 꼬리에도. 숫자·사건은 원장+시세 fresh(D5) |
| M9 | **모든 턴 산출물은 원장 역추적 가능** | 판단 로그 `fact`에 리포트 근거(debugId·heroScore·팀 요약 원문) + 테제 ID. "왜 샀다/팔았다" → 결정 덤프 → 리포트 스냅샷 → 주문 체인 (D2/D9 승계) |

> **D7 개정 통보 필요**: 본 개정은 #361 스펙(소유: feat/ai-trader-skeleton 브랜치)의 D7과 충돌 — 역반영 예정.

## 3. 턴 파이프라인 v2 (통합 — 매수/보유 동일 경로)

```
[phase=load]      상태 적재 (순수 코드)
   paper-trade: positions(수량·평단) + account(현금·실현손익)
   + 시세: 현재가·평가손익 (D5 fresh) + memory 뷰: digest→episodic + 활성 테제
        │
[phase=dump]      소스별 컨텍스트 덤프 ×3 + 보유종목 섹션   ← 반고정층 확정(바이트 고정)
        │
[phase=interest]  ② 흥미 종목 선정 턴 (LLM #1 — 캐릭터당 1회)
   페르소나가 자기 소스 덤프 소비 → {신규 흥미 | 보유 재확인 | 관심 소멸} + 근거 + 확신도
        │
[phase=scan]      ③ 스캔 집합 = 흥미종목 ∪ 보유종목(전부 — 소멸 포함, 우선 배치)
   ④ 딥스캔 실행(불투명 함수) — 보유종목은 holding context 실어 호출 → 조언 생산
        │
[phase=decide]    ⑤ 매매 결정 턴 (LLM #2 — prefix 재사용)   ← 신규
   같은 [시스템+①덤프] prefix(캐시 hit) + 꼬리: ②흥미 결과 + ④위원회 조언(hero 점수+3팀 청크)
   + 활성 테제 원문 + 기억 요약 + 계좌 fact(현금·평가손익·보유 종목 수·현금 비율·연속 손실·목표 진행률) + 가드레일 고지
   → 종목별 {BUY/SELL/HOLD + amountKrw + 근거 서사} — 결정과 서사가 한 몸
        │
[phase=execute]   실행 (가드레일 물리 강제)
   단가 = 실행 시점 시가 고정 · 수량 = floor(min(amountKrw, 가용잔고)/시가) fit 치환
   paper-trade POST /orders → 판단 로그 저장(side·thesis_id·fact{debugId, heroScore, 팀 요약})
        │
[phase=compile]   턴 종료 (장마감 후 1회)
   event extractor(코드): 원장 diff → typed events
   memory compiler(LLM): 기억 라인 → published · 일기(LLM #3): diary_entries 저장 → completed
```

재시작 시: 마지막 완료 phase 다음부터 재개. 체결 주문은 원장 diff로 중복 방지.

## 4. 컨텍스트 덤프 명세 (①의 내용 — 조율 본체)

### 4.1 소스별 종목 덤프 (근거 포함 — 페르소나 선정의 입력)

| 소스 | 덤프 내용 | 근거 형태 | 실측 소스 |
|---|---|---|---|
| 뉴스 | 메인뉴스 50건 (제목+요약+종목 추출) | 기사 그 자체 — 50개 중에서 선택 | naver-mainnews :13020 `/api/news?limit=50&fresh=1` |
| 차트 | 스크리너 상위 N 종목별 **패턴 나열**+점수 | 패턴 목록을 보고 선택 | krchart :13100 `/api/screener?top=N&direction=bullish` |
| 재무 | 재무점수 랭킹 상위 종목별 카테고리 점수 | 점수 내역(수익성/안정성/성장성…)으로 평가 | dart-fs :8088 `/api/scores/rank?top=30` |

### 4.2 보유종목 섹션 (Q1 확정 — 덤프에 포함, ②절차가 심사)

```
## 보유 종목 — 매도/홀드 심사 대상
### 케이아이엔엑스 (093320) · 12주 · 평단 32,400 · 현재 31,100 (−4.0%)
- 진입 근거(3일 전): 차트 베이스 돌파 + 재무 안정성 상위권
- 오늘 소스 증거: [차트] bearish 41, 상위권 이탈 · [재무] total 71 (88위) · [뉴스] 언급 없음
```

소스 증거 리프레시(보유분, M6 구현 재료 — 실측 완료):
- 차트: `/api/analyze?symbol={code}` 종목별 패턴 분석 + `direction=bearish` 스크리너
- 재무: `/api/scores/rank` 전체(2,094종목, 캐시됨) → 보유 코드만 뽑기
- 뉴스: 50건 중 보유종목 언급 필터 — "언급 없음"도 정보

### 4.3 위원회 조언 블록 (Q7 확정 — 점수와 문장 모두, 종목당 ⑤ 꼬리에)

```
## 위원회 조언 — 케이아이엔엑스 (093320)
종합 가중치 62/100 (강세) · 이것은 조언이다. 최종 결정은 당신이다.
- 시장·차트 팀: "20일선 위에서 거래량 수반 반등, 단기 추세 전환 신호."
- 심리·환경 팀: "업황 뉴스 흐름 중립, 심리 개선 국면."
- 가치·기본 팀: "최근 분기 영업이익 기대치 상회, 마진 안정."
```

- 3팀 문장은 웹 UI 로딩 화면의 세 팀 카드와 **문장 단위 동일**. 팀 요약이 스냅샷에 `(teamKey, inputKey)`로 영속화됨(`deepscan-team-summary-store`, 캐시 재사용) → 파이프라인이 공짜로 재사용. **페르소나가 보는 조언 = 사용자가 웹에서 보는 조언**
- **조언 블록 조립 절차(2026-11-20 확정 — 브라우저와 동일한 경로)**: ① `GET /api/deepscan` → ② 응답 payload의 `teamSummaries` 있으면 그대로 사용(재스캔 0 LLM) → ③ 없으면(fresh run) 로딩 화면과 동일한 team-summary 엔드포인트를 3팀 순서로 호출 → 조언 블록 3청크 확정. jaroo 코어 변경 0, "웹과 같은 3청크"가 계약으로 고정됨
- 전문 리포트는 경계 덤프(요청 파라미터+응답 스냅샷+scan id)로 저장 — ⑤에는 슬림 뷰만(꼬리는 캐시 불가라 비용 직결)

## 5. 매매 결정 턴 프롬프트 구조 (⑤ — prefix 캐시 레이어링)

```
[고정층 — 시즌 내 고정]     캐릭터 카드(성향/말투/목표) + 가드레일 고지문
[반고정층 — 턴 시작 시 확정] ①소스 덤프 + 보유종목 섹션  ← ②흥미 턴과 바이트 동일 → 캐시 hit
[가변 꼬리 — 캐시 불가]      ②흥미 결과 · ④조언 블록(종목당) · 활성 테제 원문
                           · 기억 요약(digest 1줄 + episodic 수 줄) · 계좌 fact(현금·평가손익·보유 종목 수·현금 비율·연속 손실·목표 진행률) · 출력 스키마
```

출력 스키마:

```json
{ "decisions": [{
    "code": "093320", "name": "케이아이엔엑스", "status": "existing|new",
    "action": "buy|sell|hold",
    "amountKrw": 300000,            // LLM은 금액 의사만. 단가·수량 계산 금지(가드레일)
    "sellRatio": 0.5,               // sell 한정: 전량=1.0, 분할
    "reason": "위원회는 강세지만 소스 이탈이 겹쳐 절반만 정리" }],
  "narrative": "오늘의 판단 서사 (판단 로그 rationale 그대로)" }
```

캐시 경제학: 캐시 규약은 **덤프 반고정층에만** 엄격 적용(같은 입력이 ②와 ⑤, 그리고 뉴스의 경우 캐릭터 3명이 공유). ⑤ 꼬리와 일기는 자유 조립.
> **실측(2026-11-19, OpenGateway deepseek-v4.1-flash-eco)**: prefix 캐시는 작동하나 게이트웨이 라우팅 때문에 **hit이 확률적** — 동일 요청 84%(1024/1218토큰) hit, 공유 prefix·꼬리 분기 5/8 hit, 완전 miss도 연속 2회 관찰. 따라서 캐시는 **보너스로 취급하고 비용 모델은 미hit 가정**으로 산정한다. 바이트 안정 덤프 계약은 캐시 hit 가능성 + 골든 재현성(입증) 두 가지 이유로 그대로 유지.

## 6. 가드레일 & paper-trade `fit` 모드 (Q6·ii 확정)

**paper-trade는 현재가를 모른 채 구현한다** — 시세 조회 0회 유지(quote ZERO 무결):

| 입력 | 소유자 |
|---|---|
| 잔고 cashKrw | 서버 원장 (기존에도 `insufficient_cash` 검사에 사용) |
| 단가 priceKrw | **호출자 입력(기존 계약 그대로)** — 파이프라인이 시세 소스에서 받은 시가를 강제 고정해서 실음 |
| 금액 의사 amountKrw | 신규 입력 (quantity 대체) |

```
POST /v1/accounts/{id}/orders
{ "symbol":"093320", "side":"buy",  "amountKrw":300000, "priceKrw":31100 }  // fit 매수 — priceKrw 필수(시가 고정)
{ "symbol":"093320", "side":"sell", "ratio":0.5,        "priceKrw":32000 }  // ratio 매도 — priceKrw 필수
→ 매수 qty = max q s.t. debit(q) ≤ min(amountKrw, cashKrw)  // debit = q×price×(1+수수료율) — rates 기존 엔진 승계
→ 매도 qty = floor(보유수량 × ratio)
→ qty ≥ 1 이면 체결(원장 기록) · 매수 qty=0 → unaffordable(400) · 매도 qty<1 → insufficient_ratio_quantity(400)
```

- **원자성**: 잔고 읽기→수량 계산→체결이 엔진 트랜잭션 안 — 사전 계산의 TOCTOU 제거 (ii를 고른 이유)
- **매도 대칭**: `ratio` 모드 — 체결가 원장·실현손익·거래세 정산을 위해 **priceKrw 필수**로 확정 (구현 PR #372 — v2 초안의 "가격 불필요"에서 변경)
- **구현 완료**: PR #372 (2026-11-19, 테스트 45/45) — 응답은 기존 OrderRecord 그대로 `quantity`에 치환된 수량. 모드 위반 `invalid_order_mode`(400). 원자성: 잔고 조회→치환→체결→영속화 단일 트랜잭션
- 이미 갖춰진 콜드원장 계층(실측): cashKrw 원장·SQLite WAL 영속·`avgPriceCenti` 평단·주문 저장·"체결가는 입력 priceKrw일 뿐, 시세 조회/신신도 개념 없음"(엔진 테스트 주석) — 시가 평가 계층과의 분리는 이미 설계 철학
- LLM 위반 시도(잔고 초과·보유 수량 초과 매도 등 물리 제약)는 실행 계층이 거부 + 로그 — 밴드·날짜 규칙 같은 **판단성 강제는 존재하지 않음**(2026-11-19 확정)
